# Source, licenses and relinking for 2.0.25

The release supplies these materials alongside the native assets:

- `bun-1.3.14-source.tar.gz`: Bun commit
  `0d9b296af33f2b851fcbf4df3e9ec89751734ba4`.
- `webkit-5488984d20e0dbfe4be2c3ba8fb18eb81a5e0e8b-source.tar.gz`:
  the complete patched WebKit source selected by that Bun revision.
- `bun-1.3.14-dependency-sources.tar.gz`: the 20 dependency source archives
  selected by Bun's checked-in build manifests, with their original revisions.
- `THIRD-PARTY-LICENSES.tar.gz`: original license, copyright and notice files
  from those sources and the frozen workspace dependencies. Its index records
  each file's origin and SHA-256.
- `SOURCE-MATERIALS.json` and `SOURCE-SHA256SUMS.txt`: source identities and
  checksums for these supplemental assets.

The application source and lockfile are at the `v2.0.25` Git tag and in GitHub's
source archives. The native artifact receipts identify the exact application
commit, producer run and runtime bytes. Retain the accompanying notices when
redistributing the application or its ordinary Bun runtime.

## Rebuild Bun with a modified JavaScriptCore

Extract the Bun archive and put the supplied WebKit source at `vendor/WebKit`
inside it. Keep the matching source revision before making your changes. The
dependency archives can be inspected or used to populate the dependency sources
selected by `scripts/build/deps/*.ts`; the original build manifests and patches
are included in the Bun source archive.

Install the build prerequisites in that revision's `CONTRIBUTING.md`, including
LLVM 21.1.8. Modify JavaScriptCore/WebKit, then run Bun's local-WebKit build:

```sh
bun run build:local
```

This builds Bun and its C++ bindings against the modified JavaScriptCore.
The upstream guide documents the build output and release build profiles.
See the supplied `CONTRIBUTING.md` and `scripts/build/deps/webkit.ts` for the
exact platform flags and dependency configuration.

## Relink the application

Check out the application tag, install its frozen lockfile, and rebuild the
workspace. In `packages/engine/toolchain/src/lib/bun-compile.ts`, add
`executablePath: '/absolute/path/to/your/rebuilt/bun'` to the `compile` object
passed to `Bun.build`, then rebuild the workspace toolchain. Bun's equivalent
command-line option is `--compile-executable-path`.

Use the matching platform's rebuilt Bun executable. The normal product commands
retain the application entrypoints, embedded files, definitions and native
companions:

```sh
bun install --frozen-lockfile
bun run build
bun run --cwd products/agent build:binary --target linux-x64
bun run --cwd products/tui build:linux-x64
bun run --cwd products/daemon build:binary --target linux-x64
```

For the Linux captured-REPL companion, use the matching rebuilt ordinary Bun
as `<application>.bun`, preserving its executable permission and updating the
companion provenance hash. The application and ordinary interpreter are
separate executables; rebuild both when replacing their linked JavaScriptCore.
Rebuilt files have new identities and need their own tests and receipts.
