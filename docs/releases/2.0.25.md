# GoodVibes Jev 2.0.25

This release brings shared execution modes, evidence-backed contract completion
and native Herdr session reporting to the workspace. The full user-facing change
list and migration notes are in the [engine changelog](../../packages/engine/CHANGELOG.md#2025---2026-11-05).

## Version and distribution

The root workspace, Engine, Judgment and Daemon use `2.0.25`. Agent and TUI keep
their independent product versions. Native artifacts are identified by the
workspace source commit and producer CI run, rather than by assuming every
product has the workspace version.

The release workflow stages the admitted Agent and TUI Linux x64 cohorts and
Daemon Linux x64, Linux ARM64, Darwin x64 and Darwin ARM64 cohorts. Assets include
native provenance receipts and a `SHA256SUMS.txt` manifest. Linux captured-REPL
runtime companions and their license/provenance files travel with their owning
executables. See the release policy
for runtime redistribution requirements and the artifact handoff contract.

The release also supplies pinned runtime sources, dependency sources, original
license texts and source checksums. See the [source and relinking guide](2.0.25-rebuild.md).

Registry publication is controlled by the existing `PUBLISH_NPM` repository
variable. A native GitHub release does not by itself establish an npm release.

## Upgrade notes

- Select `safe-owner`, `safe-jev` or `yolo` in settings. Saved legacy aliases
  normalize at configuration boundaries, and changing modes invalidates pending
  execution authority. `plan` remains a separate non-executing posture.
- Payment budgets, merchant restrictions and approval/veto rules continue to
  apply independently of execution mode.
- Herdr integration uses the inherited pane, binary and socket identity. It
  reports activity and owner waits without forwarding prompt or answer text.
- Contract acceptance uses the original obligations, current evidence and saved
  gate receipts. Historical completion observations cannot authorize a new
  operation.

## Release verification

The tag must point to a commit whose **push** run of `ci.yml` passed every
required job. A manual CI dispatch is not a substitute for that producer run.
The Release workflow verifies that run and restores its exact artifacts before
publishing. Do not tag a candidate with failed, missing or unfinished checks.

Completion evidence consists of the successful CI run for the tagged SHA, the
successful Release run, the published asset inventory and verified checksums.
Those are release-time evidence; this document alone does not certify a passing
run or live-provider behavior. Browser and scripted-model fixture results retain
the scope described in the [repository readiness notes](../../README.md).
