# GoodVibes JEV 3.0.0

Status: draft release notes. Development version: `3.0.0-dev.0`. Implementation
and documentation are complete. Local integrated validation has passed; CI and
native artifact qualification remain in progress. No v3 release has been published.

This major version brings the platform and four products under one version and
first-party package namespace. Protocol and storage schema versions remain
independent; upgrading package versions does not relabel persisted records.

## Changes implemented for v3 development

- Decision backends cover Jev, Clef, Clef-flash, DiffusionGemma Jev, Kev-9B and
  Laya through explicit protocol/capability adapters and independent credentials.
- Configured hosted/local targets receive finite attempts. A valid semantic
  answer ends failover; exhausted targets produce an actionable unavailable
  error and halt the operation. Cancellation and authority checks stay owned.
- The opt-in Decision Router selects a user-configured answering provider,
  model and effort per category. Empty categories use General. Routing previews
  stay bounded and separate from the normal answering context and saved transcript.
- Actual route and answering-model usage are retained. Optional volume budgets
  distinguish logical decisions, target attempts and actual wire dispatches.
- Trigger conditions reject prototype traversal, accessors and unsafe coercion.
  Equivalent late-rejection draining uses one shared helper.
- Shared terminal rendering, input, command, notification, onboarding, native
  ledger and lifecycle behavior now lives in the engine platform and terminal-shell.
  Product adapters retain their distinct authority, isolated data roots and
  presentation. The [inventory](../design/terminal-consolidation-inventory.json)
  records all 276 baseline dispositions and the audit of off-path copies.
- Synchronous autosave and shutdown callbacks now persist structured return
  context directly; they no longer silently spread an unresolved Promise.

## Configuration and diagnosis

See [decision backend configuration](../../packages/judgment/README.md#decision-backends-and-finite-failover)
for exact served model IDs, authentication and deployment limits, and
[Decision Router](../design/decision-router.md) for category settings.
On exhaustion, check the key reference for every target, endpoint reachability,
served model name, local model process, and complete-input limits. A valid
refusal does not try another model. Do not restart an unavailable operation in
an automatic consumer retry loop.

## Qualification evidence

On the consolidated development revision, packed engine and judgment packages
installed and executed under both npm/Node and Bun. The installed-package smoke check exercises all six decision adapters,
authentication/connection/protocol/timeout failover, full-chain exhaustion without
execution effects, and refusal without trying another model. These checks use
synthetic wire responses and establish integration behavior, not model accuracy.

Integrated TypeScript checks and engine, daemon, compiled Linux TUI/Agent and
WebUI builds passed. Public API/subpath reports, contract drift, package exports,
browser compatibility, packed contents, publint and installed-artifact checks
passed. Focused terminal checks cover session restore, hosted ownership, notices,
picker state, credential publication, card containment, onboarding and settings
rendering. The complete Agent input and renderer suites passed, along with the
judgment foundation suite. Real bubblewrap REPL history and cancellation proofs
passed with confinement enabled. CI remains the owner of the full platform and
product matrix on the release revision.
