# GoodVibes JEV 3.0.0

Status: draft release notes. Development version: `3.0.0-dev.0`. No v3 release,
installed-artifact qualification or green integrated CI is asserted here.

This major version brings the platform and four products under one version and
first-party package namespace. Protocol and storage schema versions remain
independent; upgrading package versions does not relabel persisted records.

## Changes implemented for v3 development

- Decision backends cover Jev, Clef, Clef-flash, DiffusionGemma Jev, Kev-9B and
  Laya through explicit protocol/capability adapters and independent credentials.
- Configured hosted/local targets receive finite attempts. A valid semantic
  answer ends failover; exhausted targets produce an actionable unavailable
  error and halt the operation. Cancellation and authority checks stay owned.
- The opt-in Decision Router selects a user-configured answering provider,
  model and effort per category. Empty categories use General. Routing previews
  stay bounded and separate from the normal answering context and saved transcript.
- Actual route and answering-model usage are retained. Optional volume budgets
  distinguish logical decisions, target attempts and actual wire dispatches.
- Trigger conditions reject prototype traversal, accessors and unsafe coercion.
  Equivalent late-rejection draining uses one shared helper.
- Terminal rendering, input, notification and native preflight behavior are
  moving into the engine platform. Product presentation remains in small adapters.
  The [inventory](../design/terminal-consolidation-inventory.json) tracks work
  still pending; this consolidation is not yet complete.

## Configuration and diagnosis

See [decision backend configuration](../../packages/judgment/README.md#decision-backends-and-finite-failover)
for exact served model IDs, authentication and deployment limits, and
[Decision Router](../design/decision-router.md) for category settings.
On exhaustion, check the key reference for every target, endpoint reachability,
served model name, local model process, and complete-input limits. A valid
refusal does not try another model. Do not restart an unavailable operation in
an automatic consumer retry loop.

## Qualification still required

Complete the remaining platform consolidation, regenerate public API/contract
artifacts and test navigation, then run integrated types/builds, deterministic
boundary/product checks, security and package checks, installed-artifact checks,
and CI on the release revision. Finalize the shared version as `3.0.0` only as

to certify their semantic accuracy; live calibration remains optional.
