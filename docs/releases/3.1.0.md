# GoodVibes 3.1.0

## Decision-model policy

The persisted `judgment.policy` setting has three exact values:

| Policy | Behavior |
| --- | --- |
| **Default - On** | Use the configured finite hosted/local decision chain; halt on exhaustion. Existing installations keep this default. |
| **Preferred** | Use that chain; continue the owning operation in Classic only after actual availability exhaustion. |
| **Classic - Off** | Use Classic from startup, with zero decision-model requests. |

Choose the policy in settings or through the existing configuration command/API.
Ordinary answering models remain available in Classic. The Decision Router uses
its configured General target and omits categorization. A policy change revokes
pending work under the previous policy; it does not silently rewrite that work's
authority.

Classic supports ordinary conversation, tools, edits, command execution, actual
test results, final answers and conversation recovery. `safe-jev` uses owner
approval handling in Classic. Explicit YOLO retains its meaning. Authentication,
workspace boundaries, secret handling, cancellation, spending rules and duplicate
execution protection remain host responsibilities.

Preferred fallback preserves history and completed work. It does not replay
executed actions or reinterpret a genuine refusal, malformed response, privacy
rejection, cancellation or stale authority as an outage. The conversation reports
the transition; tool results and final responses retain Classic provenance.
An outage cannot reopen an action already refused during that operation.

## Native behavior and explicit limits

- Native knowledge ingestion, local search, complete source quotations, manual
  review and declared links remain available. New inferred content stays an
  untrusted draft; Classic does not manufacture activation or fact-support receipts.
- Planning retains structural gaps, tasks, questions, verification instructions
  and the owner's execution approval. Structural readiness does not claim that
  a model assessed clarity.
- Browser controls remain usable while their values are suppressed without
  semantic clearance. Credential/card entry surfaces and native secret masking
  remain enforced.
- Native error reports retain actual status, errno, phase, causal and permission
  evidence. Unknown prose stays unassessed. Structured retry guidance survives;
  an unassessed number in error prose does not become a delay.
- Browser wake/error formatting and shared decision definitions retain native
  error identity without importing the server's operation-scope runtime.
- Policy-setting writes preserve successful persistence acknowledgements after
  revoking their previous operation scope. Semantic knowledge schedules paused
  by Classic retain their actual last-run timestamp and produce no run receipt;
  native maintenance schedules still dispatch normally.
- Speech uses native boundaries. Local voice provisioning runs the engines once
  and can report `classic-exact-match` for an exact ordered word sequence, with
  `native-word-sequence` as its basis and semantic assessment explicitly absent.
- Support bundles retain native diagnostics, redaction and publication ownership.
  Marketplace browsing uses literal matching and explicit selection.
- Autonomous contract execution/correction, semantic knowledge synthesis and
  independent verification, merchant/checkout interpretation, semantic marketplace
  recommendations and semantic quality grading require decision models. Their
  Classic limits are explicit; stored receipts and native inspection remain available.
- Build smoke can qualify a clean native version protocol and artifact checks.
  Extra diagnostic output holds qualification when its semantic assessment is
  unavailable; the binary is not rerun because interpretation failed.

See the [capability guide](../decision-model-policy.md) and
caller inventory for the source
dispositions. The inventory records source review, not passing workflow evidence.
Classic never fabricates model probabilities, decision IDs or semantic certificates.
