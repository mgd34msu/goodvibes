# GoodVibes 3.1.2

Status: unreleased. Final qualification of the current source, release CI and
installation of published assets remain pending.

Browser decision requests now recognize the daemon's actual listener address,
port and TLS scheme, including an automatically assigned port. A stale configured
port or forwarded request headers cannot authorize another origin. Long settings
descriptions wrap on phones without adding horizontal scrolling.
Model selection resolves exact catalog identities and Decision Router's `auto`
model directly, avoiding unnecessary decision calls. Undeclared custom provider
relationships retain their existing interpretation path.

Agent work-plan tools and terminal commands share the platform's native location
observation. A completed edit no longer leaves later reads tied to the expired
invocation. Concurrent first opens retain one assignment per project, and
read-only inspection does not create files.

Concurrent saved-state writes retain their documented publication behavior:
async durability acknowledgments finish in order, and ordinary synchronous
writes preserve the last complete value. Guarded, observed and exclusive durable
writes retain their stricter ownership checks.

Engine integrations now use `platform`, `daemon-api`, `operator-client` and
`peer-client` source paths and entry points. Update imports and factory names
from the previous first-party names when embedding the engine. The installed
application commands keep their existing names. Existing saved trigger probes
and native credentials remain readable; new writes use the current names.

Native startup activates updates and service promotion only after the complete
host boot. Handover drains the original runtime and additional listeners before
requesting service activation. Failed cleanup prevents that request and keeps
the failed-start evidence. Embedded boot failures also drain their owned
resources rather than returning a stopped server handle.

A daemon-only update from an older installation now repairs mismatched suite
programs before opening writable configuration or saved data, then starts the
repaired daemon in a fresh process. Saved automatic-update opt-out remains in
force. Missing release evidence stops the repair before startup.

Cluster transport preserves the surface identity already issued by its election
instead of carrying a second hashing fallback. Malformed surface IDs refuse
before signing; the existing cross-node privacy derivation remains in use.

Held and unavailable inbox-triage attempts now save failure metadata without
hashing message content. Existing receipts remain readable. Settled results keep
their exact-input match so stale labels cannot be applied to changed messages.
Dry-run previews also omit saved-receipt bindings and cannot be committed as
stored receipts.

Contract startup no longer runs synchronous Git subprocesses on the host event
loop. Embedded platform callers must await contract start methods and placement
helpers. AgentManager keeps ownership of preparation until it drains, including
when cancelled. Concurrent draft launches share one operation.

Shutting down the contract runner preserves resumable contract and workstream
checkpoints. Its internal signal retirement no longer records an owner
cancellation. Resumed captured repairs create a fresh executor and authority.

Native contract recovery uses a direct contract-ID index and validates the
original receipt. An unrelated damaged record no longer blocks an indexed
contract; damaged target authority still requires repair.

Native CI continuation checks compare their live configuration and workspace
revisions directly, avoiding repeated hashing during execution.
Fresh continuation grants retain the issued action identity. Invalid records
and cancelled or failed repair preparation skip unused digest calculations;
supported older saved bindings are still verified when actually needed.
Gateway scope reads also reuse their immutable registered snapshot until a
method or event changes, avoiding repeated sorting and hashing on live guards.
New continuation records use persisted execution identities rather than
repeated content hashes. Supported prior bindings retain their recorded values.

New paired-continuation custody uses issued random identities and exact private
directory/credential observations, replacing repeated state hashes. Back up the
pairing store together with its `.native-owner` file. That file carries no bearer
credential; copying it to a different owner directory does not transfer a grant.
Published v1 grants remain readable without rewriting or reissuing them, and
their old verifier is reused while its exact inputs are unchanged. Older readers
can still read the pairing records but cannot resume these newly issued grants.

Native writers record their required reader formats before retaining newer
payment, knowledge, contract, configuration and session data. Managed updates,
crash rollback and the offline native installer check those requirements before replacing
the executable cohort. A refused crash rollback names the required version and
keeps the current build. Starting without an incompatible write preserves early
rollback. The public release installer also checks existing reader requirements
using its verified staged daemon before replacing programs, while holding executable transaction
claims that prevent a native publisher from racing the check. It retains claims
after interrupted partial replacement rather than presenting a successful install.
Native CI artifacts now retain the reader profile reported by their compiled
binary. A matching version alone cannot authorize a downgrade or rollback after
newer data has been written. Older artifacts remain readable with unknown
capabilities; rollback before any incompatible data write remains available.
For installations upgraded by an older updater, the running daemon can preserve
its compiled reader support in the next update receipt. That evidence remains
bound to its original complete payload cohort, including when used for recovery.
Published native assets retain the original descriptor for released updaters
and add a separately verified reader descriptor for newer clients. The release
installer checks both against the compiled candidate before placing its receipt.

Retained gateway authorizations pin their original credential and scope ceiling.
Replacing a handler or authentication owner retires the old authorization.

Native checkout admission saves its original request and source evidence in a
separate encrypted local store before returning acceptance. Cancellation during
preparation prevents checkout execution and drains the storage work. Known-safe
settlement removes the protected request; unknown and unverified submissions
retain it. These saved facts do not grant authority to resume a checkout after
restart; native continuation independently restores the original authority,
browser and eligible polling receive span before continuing a waiting checkout.
The encrypted record now also retains a continuation issued by the original
paired owner and bound directly to the existing operation ID. Confirmed safe
settlement retires that grant before cleanup. Stopping an unknown submission
retires future authority while preserving reconciliation evidence. Parsing a
stored reference does not authorize effects or reconstruct a browser page.

Before acknowledging admission, checkout also retains native observations of
the original attached browser connection, tab/context and document loaders in
the encrypted request. The discovered WebSocket remains pinned rather than
rediscovering a browser at its old HTTP address. Protocol reads use the actual
page or its Node-host mapping and remain owned through cancellation/shutdown.
Selected control identities, frame selectors and original identity metadata are
retained alongside those observations, without entered field values. Native
snapshots are immutable and concurrent reads retain distinct snapshot IDs.
Copied JSON remains data rather than native snapshot provenance.
Recovery independently restores those controls, original window and eligible
native receive span. A launched browser without a reconnectable endpoint
does not invent an attachment record.

Purchase replies now match the acknowledged Telegram bot, chat, topic and notice.
The original verified ingress session supplies account proof; unrelated or stale
messages do not spend model calls. Missing source evidence and verification still
in flight at the deadline cannot become permission by silence. Consumed answers
receive a successful acknowledgement and do not create a chat turn. Native webhook
registration binds a private registration credential to its original Bot API
session only after acknowledgement. Shutdown, credential changes and replacement
retire that proof. Configured shared-secret ingress does not gain native payment
authority. Paired Payments controls remain available. Restart reply recovery
uses the original native polling cursor and encrypted archive described below.

Browser session and tab references are distinct across owning runtimes and
reattachments, preventing saved requests from selecting a different page after
a restart or reconnect.
Attachment uses the exact browser WebSocket selected during discovery, including
for a Node-host fallback. Explicit proxy paths and query parameters are retained.
Releasing a session or shutting down disconnects attached debugger clients while
leaving the user's browser, contexts and tabs running.
Each browser manager has one lifetime. After shutdown, new browser work uses a
newly composed manager. Provisioning, launch and attachment retain ownership
until their admitted dependencies settle, including late results after cancellation.
Node browser helpers have an awaitable close that waits for the actual helper
process and its pipes. Shutdown also retires helpers still starting or attaching,
and waits for helpers released earlier. Only the owned helper is terminated;
the external browser stays open. platform callers should await `BrowserHostClient.close()`;
`stop()` requests the same close without waiting and permanently ends that client.
Pending tab creation and page-list reads retain their original session. A late
created tab is cleaned up rather than returned for a retired session. Shutdown
waits for admitted tab creation, title reads and explicit tab/context closure;
failed cleanup remains owned and is reported.
Navigation, history traversal, page snapshots, text reads and waits also retain
the original page through their native work. They cannot publish a late result
for a closed session, and shutdown waits for those admitted reads to settle.
New-tab navigation retains the tab after creation as well.
Browser interactions and extraction retain that same page owner. Closing a tab
or session cancels its native actions and identity/quote readings; shutdown drains
their admitted work. A click that may already have dispatched stays an unknown
outcome, so checkout does not retry it or release its protected hold.
Screenshots stay in a private buffer until the page owner and payment-material
guard are checked again. The Node helper returns the complete image to that
owner instead of writing a file before those checks.
Page snapshots retain their original decision reader before browser I/O. Card-field
classification uses that reader and the original page's cancellation; a later
provider installation cannot be adopted midway through a pending snapshot.

Checkout begin now returns a durable `accepted` acknowledgement for the caller's
saved `requestId`. Processing belongs to the daemon after admission and survives
request disconnect. Reusing that ID never starts a second checkout; query its
status after a lost response. WebUI Settings → Payments → Purchases and the
shared TUI/Agent `/payments pending` view show operation status as well as live
approval windows, with an explicit stop action. A stop request does not undo a
merchant order. Restart never retries a potentially submitted charge. Eligible
pre-submit windows resume only after independently restoring their original
paired authority, native browser and receiving evidence.
Window evidence retains the exact rendered notice and, when Telegram supplies
them, the acknowledged chat/message/thread IDs. These identify the actual send,
rather than a possibly changed configured chat alias; they do not make an
interrupted checkout resumable or establish that missed replies were recovered.
Each admitted checkout also retains the original untrusted-source evidence
before asynchronous preflight. Later owner requests cannot clear or substitute
it, and repricing uses those same original facts. Incomplete original evidence
remains a refusal; unrelated later content does not taint a clean bound request.
The original paired owner, settings and browser must still remain current.
The optional `requestedMax` is now enforced against the complete payable total,
including tax, mandatory fees and delivery. It accepts one non-negative decimal
amount in the configured budget currency, without grouping or prose. Going over
it requires explicit approval, even with ample daily budget. Silence, denial or
failed delivery stops the purchase. Repricing retains the original maximum;
notices show it in browser and terminal purchase controls, and completed receipts
retain it as optional `requestedMaximumMinorUnits`.
Checkout checks the current cart, selected shipping and payable total against
the exact quote in the notice before card entry and again before submission.
The retained page observation is checked at the final click boundary as well.
A changed quote voids the earlier answer and releases its reservation. The native
adapter can read and verify replacement prices for the same purchase, including
prices in collapsed delivery selectors. Those prices receive a new budget decision,
reservation, notice and window ID; the old window cannot approve the new amount.
An incomplete or unestablished replacement stops with `total-changed`. A click
that may already have reached the merchant is never retried. Card redaction
remains active after a stopped partial fill. Split cart rows are counted together
and must match the requested quantity exactly. Parsed monetary sums must stay
within exact integer accounting.
Replies received while a purchase notice is being sent or saved stay bound to
that purchase. Channel replies are accepted after the window opens and only
where its notice was delivered. A queued reply cannot answer a replacement window.
Recovery skips live execution leases, including another process's checkout.
Pre-checkout approval grants and spends also refresh under one shared file lock.
Separate daemon instances cannot re-spend an approval from a stale in-memory
copy. Damaged approval evidence is preserved for repair, and an uncertain write
requires inspecting the actual stored state rather than restoring a cached grant.

Interrupted submission recovery now looks up the actual purchase ledger.
Recorded submissions retain their verified or unverified outcome. Damaged
purchase history reports an error and prevents new checkout admission;
it is preserved for repair. Concurrent receipt writers retain each other's
entries, and submission checks that purchase evidence remains available.

The daemon now invokes checkout recovery before attaching payment handlers,
including when no browser has been created. Shutdown waits for admitted payment
preflight, browser actions, recovery and replies before releasing their owners.
A recovery reporting timeout does not abandon the underlying work.

Damaged or unsupported payment journals now disable checkout storage without
discarding pending purchases. Failed cleanup writes remain visible, and a page
stays reserved until its checkout record is durably removed.
Card redaction also survives submission and navigation until the payment tab
closes. Use a new tab when screenshots are needed for later browser work.

Selected-item help now appears above continuous option lists across TUI and
Agent. Selection keeps the list stable, including settings, search results,
generic pickers, command completion, profiles and reasoning choices. Long help,
inline editing, mouse selection and confirmation prompts remain available.

Terminal settings now include decision-provider and model pickers, explicit
Default - On / Preferred / Classic - Off selection, execution-permission
selection including YOLO, fallback ordering, and Decision Router category,
provider, model and effort controls. WebUI has decision-provider and model
selection plus structured fallback editing. See the
[decision-model setup guide](../decision-model-policy.md) for the controls.

Model-catalog loading preserves the current reasoning-capability fields.
GPT-6.1 Sol supports xhigh and max without being downgraded to high. Stored effort
preferences survive model switches. Duplicate effort notices are removed, and
recoverable settings diagnostics stay inside the application's logging path
rather than appearing below the terminal footer.

Terminal session rename preparation is shared by both products. Saved owner
titles retain their source across rename and reload, so automatic naming cannot
replace a name the user deliberately chose.

Live autonomous action receipts reject a second claim while preserving both
the decision and its claim in the append-only audit history.

Copilot shares one live session between chat and model discovery. Account
changes retire the old session and model metadata. Provider startup exchanges a
fresh session with GitHub; earlier disk token caches are retired. Sessions and
source-credential digests are no longer written to that cache.

Connected-host operations compare their selected credentials directly within
the operation's lifetime. Credential changes invalidate queued work even when
the original credential is restored; status reads no longer hash credentials.

Knowledge snapshots use SQLite-issued row revisions instead of repeatedly hashing
complete sources, nodes, extractions and edges. The schema migration preserves
record content and existing activation receipts. Refresh unsubmitted planning or
import previews after upgrading; resume uncertain imports with their original
request ID and command.
Open knowledge-consolidation candidates also require a fresh reading after the
upgrade. Their later checks use the selected source or node's stored revision;
restoring changed content does not revive an earlier candidate.

Memory-vector caches also use revisions issued by their primary SQLite store.
Upgrading the old digest-only cache takes a snapshot and rebuilds its embeddings
once; saved memories remain intact. Later restarts reuse unchanged cache entries.
Rebuilding with a remote embedding provider may use that provider's API. Memory
search remains available through literal matching while vectors are unavailable.

Decision-model access errors name the configured provider rather than sending
all users to Jev billing. An exhausted fallback chain reports unavailability.
Completion checks recognize changed worker evidence even when its summary stays
the same. Native feedback keeps its reference role through compaction,
undo/redo, cancellation and message cleanup.

Browser code-language detection and read-aloud follow saved message revisions
instead of hashing the complete reply. Reconnecting refreshes those revisions;
stale replies remain held. Refresh an older browser tab after upgrading the daemon.

Held drafts and final repair findings recover against their original messages
within the same branch. Private observations stay out of the journal. Temporary
diagnosis candidates have a bounded live-case lifetime; an interrupted private
diagnosis may be drafted again after restart without rerunning completed work.

Draft list and get responses use a fixed redaction marker for private message
bodies. They no longer expose a repeatable digest of that text. Existing
encrypted draft bodies are preserved when the store is upgraded.

Plugin manifest trust now verifies actual Ed25519 publisher signatures. Previously
accepted HMAC signatures must be replaced and signed grants re-verified. See
the [plugin signature guide](../../packages/engine/docs/plugin-bundles.md#plugin-manifest-signatures).

Code indexing no longer hashes every chunk separately or repeats source hashing
for indexes built from an already captured run. The index upgrade preserves
existing embeddings. Runtime reference guards compare owned values directly
where a digest added no integrity check.
Optional calibration JSON now uses version 2 source observations: the Git
revision, working-tree status and native file versions. The old source `digest`
and per-file `sha256` fields are removed. `sourceStable` compares the local
observations directly; these are local change observations rather than portable
content identifiers or an archive of dirty source. Existing reports are not
rewritten, and `--source-sha` still selects the Git revision.

Mutable code-context checks also compare the run's original text directly.
Cancelling an older preparation preserves the replacement turn's index, and
closing an index releases its authorized source callbacks.
Finished turns clear their captured code context before another turn starts.
Loading PDF support no longer invalidates unrelated SQLite reads; database and
text-decoding checks still protect the original reader.

Captured commands retain the originally admitted runtime, dependency and
workspace bytes for their run. Changed or denied sources still stop execution;
staged copies are checked by exact byte comparisons. Publication checks every
staged output before changing host files and writes the retained output bytes.

New captured contract inputs use version-two receipts. Existing inputs retain
their original generation and checks when resumed. Use 3.1.2 or newer to resume
contracts created with the new receipt format.
Repeated checks of unchanged native inputs reuse their original validated file
observations. Changed files, replaced parents and altered receipt metadata still
refuse; copied or restored receipts undergo their full initial validation.

Selected-change comments use revisions issued by the checkpoint manager for its
exact diff views. Refresh an open diff after restarting the host or after its view
expires. Once intake captures a selected change, recovery keeps that original
hunk even if the working tree changes later.

Local privacy screening handles long nested assignments and stored-secret
reference chains without repeatedly scanning their remaining suffixes. Literal
credentials and card fields still refuse before any decision-model request.

Outward-content checks skip exact duplicate sources and stop comparing a field
once a source establishes taint. Independent fields still run in parallel, and
all complete inputs are checked before the first decision-model request.

Recorded decision requests reuse their captured immutable input in transport
instead of copying the whole payload again. Backend responses are consumed in
their documented direct result format after adapter-specific unwrapping.

Standalone platform safety checks accept the current working directory, external
request evidence and cancellation signal. Identical command text no longer
reuses a verdict from an earlier call. The obsolete
`forgetCatastrophicReadings()` helper is removed.

Native durable contract admission reads repository placement asynchronously
before publishing its owner or receipt. Disposing the runner cancels that
preparation and waits for its Git child to close before admission releases the
execution lease.

Contract severity readings drain admitted calls after cancellation or a sibling
failure and retain their reported usage. Late severity updates are checkpointed,
and final checkpoints precede execution lease release. Shutdown retains
resumable control state while saving late usage. A failed final write retains
the execution lease; join continues to report actual executor drainage.

Operation-scoped refusal lookup uses an exact private index instead of comparing
each tool action with every earlier refusal. Refusals remain in force for the
whole operation, including Preferred availability fallback, and shared source
and published entrypoints retain the same refusal memory.

Links on a different registrable domain refuse before any decision-model call.
Matching domains still receive semantic checks in decision mode. Classic keeps
the deterministic URL/domain checks and checks every followed redirect, with
accepted links explicitly marked as Classic.

WebUI Settings → Payments includes live purchase notices and deadline-bound
approve/deny or proceed-now/cancel controls. Both terminals expose the same
windows through `/payments pending`, with a shared picker and retained paired
host connection. Terminal shutdown cancels active and queued picker owners.
The four purchase-window methods
share the inbox used by channel replies and require the exact live window
reference. Answers require an explicit paired owner action and do not ask a
model to interpret a button click. Checkout begin returns a durable operation
acknowledgement; eligible restored windows use the same controls after arming.

Payment reply windows retain their own purchase and notice instead of a shared
last notice. Cancellation and failed or unfinished reply readings cannot become
veto silence; known failures before submission release the budget hold.
Uncertain submissions keep their existing no-automatic-retry protection.
Checkout phases become available to card-fill readers after their journal write
finishes. Failed initial writes release their page and budget reservations;
reservation capacity refuses new work instead of dropping live holds.
Checkout-owned holds now survive their temporary TTL and day rollover until
settlement. Existing budget files upgrade conservatively; malformed or unsupported
accounting disables payment budget operations instead of resetting available money.

Card entry also retains the original purchase through page, domain and card
lookups. Purchase, cancellation and address checks reach the browser field
writer; cancelled or stale preparations cannot continue with an earlier record.

Checkout now retains its original inputs and live transport/payment authority
across cart, merchant, shipping and browser awaits. Known pre-submit failures
release held budget; failures after entering the native click actuator retain
the uncertain outcome. Completed-charge accounting still finishes after caller
cancellation. Card redaction stays armed while a filled page may retain material.
Merchant include/exclude settings and seller thresholds now reach the actual
checkout service instead of stopping at their configuration reader.

Telemetry no longer hashes or strips arbitrary trace labels into padded IDs.
Each collector assigns native trace identities while retained events, errors or
active/completed spans need them. Valid native IDs keep their bits; queries,
live streams and imported OTLP logs/spans use the same retained identities.

Work plans use persistent assignments for the exact project ID and root instead
of deriving filenames from project names. Existing identifiable plans keep their
files and items. Older files without readable project metadata remain untouched;
their paths appear in the Work Plan modal and `/work-plan show` for recovery.

Workstream and attempt identifiers now retain their complete generated IDs.
Duplicate identities cannot replace an existing workstream, and terminal
attempt commands display IDs that can be copied back into the command.

Cron schedules now persist their stagger phase instead of hashing job IDs when
calculating each run. Existing next-run timestamps are preserved during migration.

New cluster groups use a directly generated public ID without an extra root
secret. Existing group IDs, join verifiers and rotation behavior are preserved.
platform callers should use `generateGroupId()`; `generateGroupRoot()` and
`deriveGroupId()` are removed.

Session verification journals now include explicit message-provenance records.
Resume sessions written with this format using 3.1.2 or newer; earlier releases
cannot restore those records.

All suite products share version 3.1.2. Install or upgrade through the
[release installer](../installation.md) or the applications' update controls.

Native unfinished payment windows now retain pre-notice polling spans linked to
their encrypted original reply archive. The actual account-bound poller drains
backlog before confirming offsets. Covered original windows retain their
deadline, and only uncovered acknowledged recipients are re-notified. Original
positive replies require complete coverage; recorded original silence cannot
be reinterpreted into an approval. The drain is bounded, and storage failures,
retention loss, clock changes, observed consumer conflicts or webhook changes
are uncovered reception rather than silence. New cursor/span formats declare
their native reader capabilities before publication.

This is observed queue/cursor continuity under exclusive native custody of the
bot token, not an independent audit of external consumers during downtime; the
Bot API offers no such retrospective audit. Webhook identity, saved reply lists
and backfill flags cannot certify absence.
