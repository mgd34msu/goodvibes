# GoodVibes 3.1.2

Contract startup no longer runs synchronous Git subprocesses on the host event
loop. Embedded SDK callers must await contract start methods and placement
helpers. AgentManager keeps ownership of preparation until it drains, including
when cancelled. Concurrent draft launches share one operation.

Native contract recovery uses a direct contract-ID index and validates the
original receipt. An unrelated damaged record no longer blocks an indexed
contract; damaged target authority still requires repair.

The daemon now invokes checkout recovery before attaching payment handlers,
including when no browser has been created. Shutdown waits for admitted payment
preflight, browser actions, recovery and replies before releasing their owners.
A recovery reporting timeout does not abandon the underlying work.

Damaged or unsupported payment journals now disable checkout storage without
discarding pending purchases. Failed cleanup writes remain visible, and a page
stays reserved until its checkout record is durably removed.
Card redaction also survives submission and navigation until the payment tab
closes. Use a new tab when screenshots are needed for later browser work.

Selected-item help now appears above continuous option lists across TUI and
Agent. Selection keeps the list stable, including settings, search results,
generic pickers, command completion, profiles and reasoning choices. Long help,
inline editing, mouse selection and confirmation prompts remain available.

Terminal settings now include decision-provider and model pickers, explicit
Default - On / Preferred / Classic - Off selection, execution-permission
selection including YOLO, fallback ordering, and Decision Router category,
provider, model and effort controls. WebUI has decision-provider and model
selection plus structured fallback editing. See the
[decision-model setup guide](../decision-model-policy.md) for the controls.

Model-catalog loading preserves the current reasoning-capability fields.
GPT-6.1 Sol supports xhigh and max without being downgraded to high. Stored effort
preferences survive model switches. Duplicate effort notices are removed, and
recoverable settings diagnostics stay inside the application's logging path
rather than appearing below the terminal footer.

Live autonomous action receipts reject a second claim while preserving both
the decision and its claim in the append-only audit history.

Connected-host operations compare their selected credentials directly within
the operation's lifetime. Credential changes invalidate queued work even when
the original credential is restored; status reads no longer hash credentials.

Knowledge snapshots use SQLite-issued row revisions instead of repeatedly hashing
complete sources, nodes, extractions and edges. The schema migration preserves
record content and existing activation receipts. Refresh unsubmitted planning or
import previews after upgrading; resume uncertain imports with their original
request ID and command.
Open knowledge-consolidation candidates also require a fresh reading after the
upgrade. Their later checks use the selected source or node's stored revision;
restoring changed content does not revive an earlier candidate.

Memory-vector caches also use revisions issued by their primary SQLite store.
Upgrading the old digest-only cache takes a snapshot and rebuilds its embeddings
once; saved memories remain intact. Later restarts reuse unchanged cache entries.
Rebuilding with a remote embedding provider may use that provider's API. Memory
search remains available through literal matching while vectors are unavailable.

Decision-model access errors name the configured provider rather than sending
all users to Jev billing. An exhausted fallback chain reports unavailability.
Completion checks recognize changed worker evidence even when its summary stays
the same. Native feedback keeps its reference role through compaction,
undo/redo, cancellation and message cleanup.

Browser code-language detection and read-aloud follow saved message revisions
instead of hashing the complete reply. Reconnecting refreshes those revisions;
stale replies remain held. Refresh an older browser tab after upgrading the daemon.

Held drafts and final repair findings recover against their original messages
within the same branch. Private observations stay out of the journal. Temporary
diagnosis candidates have a bounded live-case lifetime; an interrupted private
diagnosis may be drafted again after restart without rerunning completed work.

Draft list and get responses use a fixed redaction marker for private message
bodies. They no longer expose a repeatable digest of that text. Existing
encrypted draft bodies are preserved when the store is upgraded.

Plugin manifest trust now verifies actual Ed25519 publisher signatures. Previously
accepted HMAC signatures must be replaced and signed grants re-verified. See
the [plugin signature guide](../../packages/engine/docs/plugin-bundles.md#plugin-manifest-signatures).

Code indexing no longer hashes every chunk separately or repeats source hashing
for indexes built from an already captured run. The index upgrade preserves
existing embeddings. Runtime reference guards compare owned values directly
where a digest added no integrity check.
Mutable code-context checks also compare the run's original text directly.
Cancelling an older preparation preserves the replacement turn's index, and
closing an index releases its authorized source callbacks.

Captured commands retain the originally admitted runtime, dependency and
workspace bytes for their run. Changed or denied sources still stop execution;
staged copies are checked by exact byte comparisons. Publication checks every
staged output before changing host files and writes the retained output bytes.

New captured contract inputs use version-two receipts. Existing inputs retain
their original generation and checks when resumed. Use 3.1.2 or newer to resume
contracts created with the new receipt format.

Selected-change comments use revisions issued by the checkpoint manager for its
exact diff views. Refresh an open diff after restarting the host or after its view
expires. Once intake captures a selected change, recovery keeps that original
hunk even if the working tree changes later.

Local privacy screening handles long nested assignments and stored-secret
reference chains without repeatedly scanning their remaining suffixes. Literal
credentials and card fields still refuse before any decision-model request.

Outward-content checks skip exact duplicate sources and stop comparing a field
once a source establishes taint. Independent fields still run in parallel, and
all complete inputs are checked before the first decision-model request.

Recorded decision requests reuse their captured immutable input in transport
instead of copying the whole payload again. Backend responses are consumed in
their documented direct result format after adapter-specific unwrapping.

Standalone SDK safety checks accept the current working directory, external
request evidence and cancellation signal. Identical command text no longer
reuses a verdict from an earlier call. The obsolete
`forgetCatastrophicReadings()` helper is removed.

Native durable contract admission reads repository placement asynchronously
before publishing its owner or receipt. Disposing the runner cancels that
preparation and waits for its Git child to close before admission releases the
execution lease.

Contract severity readings drain admitted calls after cancellation or a sibling
failure and retain their reported usage. Late severity updates are checkpointed,
and final checkpoints precede execution lease release. Shutdown retains
resumable control state while saving late usage. A failed final write retains
the execution lease; join continues to report actual executor drainage.

Operation-scoped refusal lookup uses an exact private index instead of comparing
each tool action with every earlier refusal. Refusals remain in force for the
whole operation, including Preferred availability fallback, and shared source
and published entrypoints retain the same refusal memory.

Links on a different registrable domain refuse before any decision-model call.
Matching domains still receive semantic checks in decision mode. Classic keeps
the deterministic URL/domain checks and checks every followed redirect, with
accepted links explicitly marked as Classic.

WebUI Settings → Payments includes live purchase notices and deadline-bound
approve/deny or proceed-now/cancel controls. Both terminals expose the same
windows through `/payments pending`, with a shared picker and retained paired
host connection. Terminal shutdown cancels active and queued picker owners.
The four purchase-window methods
share the inbox used by channel replies and require the exact live window
reference. Answers require an explicit paired owner action and do not ask a
model to interpret a button click. Checkout begin still waits inline; detached
operation acknowledgement and restart-resumable window controls are unfinished.

Payment reply windows retain their own purchase and notice instead of a shared
last notice. Cancellation and failed or unfinished reply readings cannot become
veto silence; known failures before submission release the budget hold.
Uncertain submissions keep their existing no-automatic-retry protection.
Checkout phases become available to card-fill readers after their journal write
finishes. Failed initial writes release their page and budget reservations;
reservation capacity refuses new work instead of dropping live holds.
Checkout-owned holds now survive their temporary TTL and day rollover until
settlement. Existing budget files upgrade conservatively; malformed or unsupported
accounting disables payment budget operations instead of resetting available money.

Card entry also retains the original purchase through page, domain and card
lookups. Purchase, cancellation and address checks reach the browser field
writer; cancelled or stale preparations cannot continue with an earlier record.

Checkout now retains its original inputs and live transport/payment authority
across cart, merchant, shipping and browser awaits. Known pre-submit failures
release held budget; failures after entering the native click actuator retain
the uncertain outcome. Completed-charge accounting still finishes after caller
cancellation. Card redaction stays armed while a filled page may retain material.
Merchant include/exclude settings and seller thresholds now reach the actual
checkout service instead of stopping at their configuration reader.

Telemetry no longer hashes or strips arbitrary trace labels into padded IDs.
Each collector assigns native trace identities while retained events, errors or
active/completed spans need them. Valid native IDs keep their bits; queries,
live streams and imported OTLP logs/spans use the same retained identities.

Work plans use persistent assignments for the exact project ID and root instead
of deriving filenames from project names. Existing identifiable plans keep their
files and items. Older files without readable project metadata remain untouched;
their paths appear in the Work Plan modal and `/work-plan show` for recovery.

Cron schedules now persist their stagger phase instead of hashing job IDs when
calculating each run. Existing next-run timestamps are preserved during migration.

New cluster groups use a directly generated public ID without an extra root
secret. Existing group IDs, join verifiers and rotation behavior are preserved.
SDK callers should use `generateGroupId()`; `generateGroupRoot()` and
`deriveGroupId()` are removed.

Session verification journals now include explicit message-provenance records.
Resume sessions written with this format using 3.1.2 or newer; earlier releases
cannot restore those records.

All suite products share version 3.1.2. Install or upgrade through the
[release installer](../installation.md) or the applications' update controls.
