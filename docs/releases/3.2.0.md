# GoodVibes 3.2.0

This release makes status handling consistent across the product. Records that
have a status (agent runs, tasks, triggers, MCP servers, plugins, channel
connections, queries, research runs and many more) now declare which moves are
legal. A finished record is no longer overwritten by a late result, a stopped
component is no longer revived by work that was still in flight, and a failed
step no longer leaves a record stuck in an intermediate state. When an action
is refused, the message names the current status and the moves that remain.

The installers now back up what they replace and put it back when an
installation fails or is interrupted. Several repeated SHA-256 computations
were removed, and the test runner and CI were reduced to what is in use.

## Installer

- **Automatic rollback.** Previously, an installation that failed or was
  interrupted after replacement had begun left a mix of old and new programs
  and kept its claims, so the next attempt was refused until the files were
  inspected by hand. The release installer now keeps each replaced file beside
  the original as `<file>.goodvibes-previous`. On failure, Ctrl-C, a
  termination signal or a closed terminal it restores the previous files,
  removes the files it had newly created, releases its claims and prints the
  command to run again. Running services are not touched by this recovery.
- **When rollback cannot finish.** If a previous file cannot be put back, the
  claims and backups stay in place and the installer prints one restore
  command per file, followed by the command that removes the claims.
- **Leftover backups are refused up front.** An installer that was killed
  outright cannot recover. The next run now stops before changing anything,
  lists every leftover `.goodvibes-previous` file in one message and prints the
  command that removes them. Leftover backups are never restored
  automatically, because they may be older than the installed programs.
- **Publication order.** Companion files are now published before the main
  program, so a program is never present without the files it needs.
- **Updated directories are cleaned up.** Each update of the WebUI or browser
  driver used to leave the previous directory behind permanently. It is now
  removed once the whole installation has finished. A failed update keeps it.
- **Processes started by hand.** A daemon or agent running outside a service
  was restarted by replaying its arguments unquoted, which mangled arguments
  containing spaces or wildcard characters. Such a process is now left running
  and the installer prints a fully quoted command for starting the new program.
- **macOS LaunchAgent.** If a LaunchAgent rewritten with new launch arguments
  cannot be loaded, the previous file is restored and loaded again. If that
  also fails, the installer prints the `launchctl bootstrap` command to run.
- **Uninstall.** An uninstall that stops during its service and process step
  now says what was already done, confirms that no program file was removed
  and gives the command to run again. The checkout uninstaller can be run
  again after a partial uninstall; it no longer fails trying to stop a service
  whose unit is already gone.
- **Checkout installer recovery.** A checkout installation
  (`scripts/install.ts`) that failed restored the previous version, but one
  interrupted with Ctrl-C or a termination signal left the service stopped and
  both locks held. An interrupted installation now runs the same recovery: it
  restores the previously installed version, restarts the service if it was
  running, releases its locks and exits with status 130 or 143.
- **Lock owner record.** The install and uninstall locks now record the
  process that holds them. A lock left by a process that is no longer running
  is reclaimed automatically. A lock held by a running process is refused and
  names its pid. A lock with no owner record is refused with the `rmdir`
  command that removes it.
- **TUI pairing no longer blocks installation.** If an earlier pairing attempt
  was recorded as unfinished, every later checkout installation failed at the
  pairing step and rolled back. The pairing helper now exits with status 75
  and explains what happened, which token may need revoking and which record to
  clear. The installer treats that status as "pairing skipped": the
  installation completes, the daemon keeps running, and the command that pairs
  afterwards is printed. Any other pairing failure still fails the
  installation and restores the previous version.
- **TUI package postinstall.** The npm postinstall step removed the existing
  binary before copying the new one. It now stages the new binary beside the
  destination and renames it into place, so an interrupted run leaves the
  previous binary intact.

## Agents, tasks and tools

- **Agent runs.** A run that was cancelled could be relabelled `failed` when
  its executor rejected afterwards. A cancelled run now stays cancelled, a run
  that already failed keeps its first error, and the late rejection is logged.
- **Tasks.** `completed`, `failed` and `cancelled` are final. A late report
  from a runner no longer changes a finished task or rewrites its end time,
  and a process-backed task is no longer re-finished on every sync. An
  explicit retry is the only way out of `failed` or `cancelled`.
- **Task retry over the daemon API.** Retrying a completed agent task used to
  start a new agent that the task did not track, while reporting success. The
  request is now refused with status 400 and the message "Task cannot be
  retried: only failed or cancelled tasks can be retried", and no agent is
  started.
- **Session task graph.** A status update for a task that has already
  finished is ignored instead of reopening it.
- **`query` tool.** A closed query could still be answered or closed again.
  Both are now refused. An answer can still be revised until the query is
  closed.
- **`packet` tool.** Publishing an already published packet silently replaced
  its publish time. A second publish is now refused and reports the original
  time. Revising a published packet still works.
- **`workflow` tool.** Cancelling a workflow that had already finished or been
  cancelled marked it cancelled again. It is now refused with the reason and
  the completion time is unchanged.
- **Execution plans.** A plan marked complete or failed stayed that way when
  unfinished work reappeared. It now returns to active. A dismissed plan stays
  dismissed.
- **Tool calls.** Once a tool call has succeeded, failed or been cancelled, a
  later event can no longer move it to a different outcome.
- **Cancelled tool execution.** A tool run that was cancelled and then failed
  reported the failure. The cancellation now stands.
- **Sandbox sessions.** A stopped sandbox session could be moved back to
  running or failed by a late exit, and still accepted commands. Stopped is
  now final: running a command in a stopped session is refused with the
  reason, and stopping it twice is harmless.
- **Background processes.** A background process whose output collection
  failed stayed listed as running indefinitely. Its process group is now
  terminated again; once it is confirmed gone the entry is finished and can be
  pruned.
- **Work items.** A work item that was killed and whose run then threw was put
  back in the queue and run again when retries were enabled. A finished item
  is now left as it is.
- **Work proposals.** A proposal that had not been delivered could be
  answered. It can no longer be resolved until it has been delivered.
- **Follow-up delivery.** A follow-up that could not be delivered was retried
  without limit. It is now retried up to five times, with a delay that starts
  at 250 ms, doubles per attempt and is capped at 30 seconds. After the last
  attempt it is dropped and the user is told.
- **Hosted sessions.** A turn-end event for a session that was not running
  increased the turn count and announced the end a second time. It is now
  ignored.
- **Fleet view and cost rows.** A cancelled agent stayed in the fleet overlay,
  and a stream retry could show a finished agent as live. The cancelled entry
  is now removed and a finished entry is not revived by a retry. In the cost
  tracker, done and failed no longer overwrite each other and a cancelled row
  stays cancelled.
- **Idempotent requests.** A completed request record could be marked failed
  afterwards, losing its cached result. Completion and failure now apply only
  to a request that is still in flight.
- **Watchers.** A watcher stopped or removed while a run was in progress was
  put back to running, or re-inserted, when the run finished. It now stays
  stopped or removed.
- **Compaction.** After a check that found the session below its threshold,
  the stored status stayed at "checking", so session maintenance reported that
  compaction was running. After a successful run it stayed at "done". Both now
  return to idle.
- **Plugins.** A plugin whose unload threw stayed in `unloading`. The error is
  now recorded, a plugin error is reported and the plugin ends `disabled`.
  Plugin error and disabled events are sent only when the status change
  actually applied.

## Automation and triggers

- **Start and stop.** If automation was stopped while it was still loading,
  the pending start went on to mark the manager running and arm its timers. A
  start that belongs to a stopped lifetime now does nothing, and a start
  requested after the stop runs properly.
- **Cancelled runs.** A check-in or job run that was cancelled while it was
  executing was overwritten as completed or failed when the work finished. A
  cancelled run now stays cancelled and is not counted as a result.
- **Delivery attempts.** If recording the start of a delivery attempt failed,
  the whole delivery was abandoned. The message is now sent anyway and its
  outcome is recorded.
- **Trigger reset.** Resetting a running, fired or cancelled trigger could
  revive it or start it twice. Reset now applies only to `idle`, `backoff`,
  `circuit-open` and `failed` triggers; otherwise it is refused and the
  refusal says what to do instead.
- **Trigger cancel.** Cancelling a trigger that had already fired changed it
  to cancelled, and each repeated cancel added a "skipped" run to its history.
  A fired or cancelled trigger is now returned unchanged.
- **Batch jobs.** A batch job cancelled while its batch was being submitted to
  the provider was overwritten as submitted. It now stays cancelled, a job
  cancelled before the request is sent is left out of it, and the provider's
  results for cancelled jobs are ignored.

## Channels and integrations

- **Slack and Discord sockets.** A deliberate stop was reported as a lost
  connection, and a late close from an old socket could mark a newer
  connection as stopped. Stops are now silent and events from a superseded
  socket are ignored.
- **Slack and Discord start and stop.** Two concurrent starts opened two
  sockets, and a stop issued while a start was in progress reported "stopped"
  and then let the connection open anyway. Concurrent starts now share one
  attempt, and a stop during a start cancels it.
- **MCP stdio servers.** A server that crashed before completing protocol
  negotiation was restarted without limit, and a restart whose negotiation
  failed was left running and reported as connected. The attempt count now
  resets only after a successful negotiation, so such a server is given up on
  after three attempts and reported disconnected. A process ended by a signal
  is no longer treated as connected, and disconnecting cancels a pending
  restart.
- **MCP server stop during connect.** Stopping a server while it was
  connecting announced it as connected afterwards and left its process
  running. The late connection is now closed, nothing is announced and no
  reconnect is scheduled. MCP connection events are sent only when the status
  change applied.
- **ACP hosted agents.** When a hosted ACP agent reported a cancelled turn,
  the agent was shown as stopped while still alive; it refused further prompts
  and was later relabelled failed. It now returns to idle and accepts prompts.
  Only an explicit stop or a failure ends it.
- **ACP subagent runs.** Cancelling a run produced two terminal events, a
  failure followed by a cancellation. A run now emits one terminal event, and
  a cancelled run reads as cancelled.
- **Delegated Telegram intake.** A request whose decision step failed stayed
  in "deciding" and could not be decided again; it now returns to waiting for
  the owner. A cancel arriving after the work was handed over no longer
  overwrites the recorded state, and a late denial no longer overwrites a
  cancellation.
- **Relay registration.** A daemon whose relay connection opened but never
  completed registration, or received an error before registering, waited
  indefinitely. The connection is now closed after the registration deadline
  (`registrationTimeoutMs`, 15 seconds by default) or on such an error, and
  retried with the normal reconnect backoff.
- **Realtime transport.** A connector that connected without returning a
  cleanup function was connected a second time by the next subscription. It
  now connects once. Disposing a connector that had given up reconnecting
  emitted `disconnected` over `failed`; `failed` is now final.
- **Agent channel drafts.** A queued draft could be queued again and delivered
  twice, and a sent draft could be marked failed. A draft that is already
  queued is now refused while delivery is in progress, a sent draft is final
  and a failed draft can be queued again. A draft left queued with no recorded
  outcome for 10 minutes can be queued again.

## Daemon and cluster

- **Cluster node start.** A node whose transport failed to start was left
  marked as running and could not be started again. A failed start is now
  cleaned up and can be retried.
- **Daemon host.** A daemon whose startup failed is now reported as `failed`
  before it begins closing, instead of appearing to be starting until it
  closed.
- **Inbox eligibility.** One failed registration stopped inbox eligibility
  probing for the rest of the daemon's life without any message. The failure
  is now logged and the next scheduled probe tries again. Only a failed
  retirement stops probing, and that is logged once.
- **Service migration.** If `goodvibes-daemon migrate-service` started the new
  managed unit but could not finish retiring the old one, a retry was refused
  because the managed unit already existed. Running
  `goodvibes-daemon migrate-service -y` again now resumes: when the managed
  unit is installed, running and identical to the definition the tool writes,
  only the remaining retirement steps run. A managed unit that differs is
  still refused, and the messages for an incomplete retirement print the retry
  command.
- **Pair requests.** Rejecting a pair request that had already been verified,
  had expired or had been rejected overwrote its status. The request is now
  returned unchanged with its actual status, and expired requests are expired
  before the rejection is considered.

## Knowledge

- **Interrupted job runs.** A knowledge job run whose process exited was left
  `queued` or `running` permanently. When the knowledge service initializes, a
  run that is still in one of those states more than six hours after it was
  requested, and that the current process did not start, is recorded as
  `failed` with an "interrupted" error.
- **Failed job start.** If recording the start of a job run failed, the run
  stayed `queued`. It is now recorded as `failed`. A run that has already been
  settled is not overwritten by a later failure.
- **Project store after a secret is saved.** Saving a secret tightens the
  permissions of the project `.goodvibes` directory. The project planning
  registry treated that change as an unexpected modification and refused to
  open for the rest of the process. A tightening of permissions to private is
  now accepted.

## Voice

- **Stopping wake-word listening and push-to-talk.** If releasing the audio
  stream failed, the stop call rejected and the listener or capture was left
  in a stopping state. The state now always reaches stopped or idle, and the
  error is reported through the failure callback instead.
- **Push-to-talk audio is kept.** A push-to-talk stop whose stream failed to
  release lost the captured audio. The captured utterance is now returned.
- **Wake word in the terminal apps.** A wake-word detector that failed while
  starting left wake listening unable to start again and surfaced as an
  unhandled error. The failure is now shown as a notice, the listener is
  cleared and a later refresh can start it. Stopping wake listening also
  clears an earlier refusal.
- **Wake word in the Web UI.** A transcript that finished while push-to-talk
  held the microphone switched the wake host back to listening; it now stays
  suspended. Clearing a latched wake host now actually restarts listening.
- **Web UI microphone.** Releasing push-to-talk, or leaving the page, while
  the microphone was still being acquired could leave the microphone held. A
  cancelled start now releases it and never opens the microphone, and a second
  press while one is starting is ignored.
- **Web UI speech playback.** A reply whose audio could not be queued left
  playback stuck. Playback now stops and shows "The audio for this reply could
  not be played."
- **Installed model verification.** See [Performance](#performance).

## Web UI

- **Stopping a reply.** After Stop was pressed, a late text or tool frame
  switched the status back to streaming, and a failed stop request could
  replace an already finished turn with an error. "Stopping" is now kept until
  the turn ends, and a finished turn keeps its outcome.
- **Turns started elsewhere.** A turn started by another client, or already
  running when the page opened, could be shown as completed at once because an
  earlier reply was counted as the new one. Existing replies are now excluded
  when such a turn begins.
- **Live update errors.** Session, hosted session, approval and compaction
  streams could display the daemon's raw error response. They now show a fixed
  message. When reconnect attempts run out, the message says so and, for
  hosted session output, says to reload, instead of claiming to be
  reconnecting.
- **Pairing links.** Reopening a view after a pairing link had been processed
  showed "pending" again, or decoded and stored the pairing a second time. The
  recorded outcome, success or error, is now shown without repeating the work.
- **Phone node pairing.** A failed re-pair while a valid pairing was stored
  left the phone node in an error state; it now stays connected and says the
  previous pairing is still in use. Finishing pairing after a stop works
  again, and an interrupted check says to press Finish pairing again.
- **Relay connection.** A relay client dropped because no pairing was stored
  is now closed instead of being left open.
- **Offline shell.** A failed precache during service worker installation is
  now logged as a warning; installation still completes.
- **Native intake form.** A failed connection left the form unusable until the
  page was reloaded. It now shows a "Retry connection" button.
- **Session rewind.** Scope, anchor, preview and the Rewind button are
  disabled while a rewind is being applied. After a refused rewind the button
  stays disabled until a new preview is taken.
- **Hosted sessions.** Killing a session and then selecting another no longer
  applies the kill result to the newly selected session.
- **Dates.** A preview that returns after the draft was edited is discarded
  instead of being shown against the changed draft.
- **Chat search.** A failed "load more" for a search that has since been
  replaced no longer shows its error on the current search.
- **Attempt comparison.** A judge result that arrives after the operator has
  chosen an attempt by hand is still shown but no longer replaces that choice.
- **Owner profile.** A field editor or add-line form closed and discarded the
  typed text even when the daemon refused the change. It now closes only on
  success.
- **Reverting a hunk.** Preview and apply results for a hunk other than the
  one currently being reverted are ignored.
- **Hunk comments.** The comment sheet can no longer be dismissed with Escape
  or the backdrop while a comment is being sent.
- **Queued messages and pairing tokens.** A save that finishes late closes
  only the editor it belongs to, not one opened since.
- **New chat label.** After using Back to return to a session, the header and
  sidebar still read "New chat". They now show the session.
- **Composer press-and-hold.** A second press no longer leaves the first
  press's timer running, and the timer is cleared when the composer is
  removed.
- **Library.** The add-memory dialog always opens clean, and a save that
  finishes after the dialog was reopened no longer affects the new dialog.

## Terminal apps

- **Model picker.** Escape from the reasoning-effort or context-cap step
  closed the picker or returned to the wrong list. Escape now goes back one
  level at a time, and reopening the picker starts from a clean state.
- **Escape with stacked dialogs.** Closing a dialog could leave an entry for a
  dialog that could not be reopened, so a later Escape appeared to do nothing.
  Escape now reopens the previous dialog when it can be reopened, skips
  entries that cannot, and restores input focus when none remain.
- **Host pairing.** A failed pairing preview left keyboard input captured. The
  input is now released and the app prints "Pairing preview failed: ... No
  pairing request was made."
- **Work submission.** A submission that ended without a result left its
  pending line on screen. The line is now cleared.
- **MCP workspace.** A slow tool refresh could overwrite the result of a newer
  one, or leave the loading indicator on after the workspace was closed. Only
  the most recent refresh is applied.
- **Agent exit.** One failing subscription clean-up could skip saving the
  session, and a shutdown that hung held the process open indefinitely. Every
  clean-up now runs, and shutdown is bounded at 10 seconds. If the deadline is
  reached, the recovery snapshot is kept so the next launch can restore the
  session, and a restart onto an updated program is skipped with a notice.
- **Agent research runs.** `start` now applies only to a planned run, `resume`
  only to a paused or blocked run, and `pause` only to a running run. A
  refused action names the one that applies. Cancelled, completed and failed
  runs are final.
- **Agent research sources.** A source can be marked used only after it has
  been reviewed. Marking an unreviewed or rejected source as used is refused.
- **Agent document suggestions.** Accepting a suggestion that was already
  rejected, or rejecting one that was already accepted, is refused with the
  reason. Repeating the same decision is still harmless.

## Performance

- **Completion contract listings.** Each listing of response-completion
  contracts recomputed SHA-256 digests of the answer and its source text. The
  digest is now reused while the value is unchanged.
- **Wake-word model checks.** Wake-word status and recovery re-hashed every
  installed model file on each check. The hash of an installed file is now
  reused while its device, inode, size and timestamps are unchanged. A file
  that was written or replaced is hashed again, and downloads are always
  hashed in full.

## SDK and API changes

Added:

- `defineLifecycle`, `LifecycleMachine`, `LifecycleTransitions`,
  `LifecycleCheck` and `IllegalLifecycleTransitionError`, exported from
  `@goodvibes-jev/engine/platform/platform/utils`. `defineLifecycle(name,
  table)` declares the legal moves of a status and returns `can`, `check`,
  `assert`, `next`, `isTerminal`, `isState` and `describe`. A refused `check`
  carries the reason and the moves that are allowed.
- Lifecycle tables for the records listed above, exported from their owning
  modules. These include `taskLifecycle`, `agentRunLifecycle`,
  `triggerLifecycle`, `workItemLifecycle`, `mcpServerLifecycle`,
  `pluginLifecycle`, `compactionLifecycle`, `automationRunLifecycle`,
  `automationJobLifecycle`, `daemonBatchJobLifecycle`,
  `knowledgeJobRunLifecycle`, `workProposalLifecycle`, `watcherLifecycle`,
  `sandboxSessionLifecycle`, `pairRequestLifecycle`, `idempotencyLifecycle`,
  `agentCostLifecycle`, `worktreeStateLifecycle`,
  `projectWorkPlanTaskLifecycle` and `nativeConversationTurnLifecycle`.
- Task helpers `canRetry`, `canMirror` and `RETRYABLE_TASK_STATES`.
- `derivePlanStatus` for execution plans, `checkReset` and
  `TriggerManager.resetRefusal(id)` for triggers,
  `WorkflowManager.cancelRefusal(id)` for workflows, and
  `reopenFailedRepairPlanning` for contracts.
- `registrationTimeoutMs` on the relay daemon registration options and an
  optional `retry` policy (`OrchestratorFollowUpRetryPolicy`) on the follow-up
  runtime options.
- Terminal shell: `MODAL_NAMES`, `ModalName`, `isModalName`, `isModalActive`,
  `HostPairingPreview` and `ModelPickerModal.popLevel()`.

Changed:

- Terminal shell: `closeModalByName` and `reopenModalByName` take a
  `ModalName` instead of a `string`. `reopenModalByName` returns a `boolean`.
  `getActiveModalName` returns `ModalName | null`, and
  `TerminalInputHandlerState.modalStack` is `ModalName[]`.
- `McpServerLifecycleState` is now an alias of `McpServerState`. The set of
  states is unchanged.
- `WorkflowManager.cancel(id)` returns `false` for a workflow that has
  finished or was already cancelled. `TriggerManager.reset(id)` returns `null`
  for a running, fired or cancelled trigger.

Removed:

- `suiteWorkflowProblems` from the toolchain package.
- `runOwnedTestChild`, `withRunTmpDir` and the `OwnedTestChildResult` and
  `OwnedTestChildStop` types from the toolchain test-runner entry point. It
  now exports `makeTestTempDir`, `testTempRoot`, `sweepStaleTmpDirs`,
  `RUN_TMP_PREFIX` and `TEST_TMP_ROOT_ENV` alongside
  `isolatedTestEnvironment`.

## Upgrade notes

Most changes turn a silent overwrite into a refusal or a no-op. The following
can be noticed by an operator, a script or an integration.

- **Installer.** A failed or interrupted release installation now restores the
  previous programs and releases its claims. A run that finds leftover
  `.goodvibes-previous` files stops before changing anything; remove them with
  the printed command and run the installer again.
- **Installer exit statuses.** The checkout installer exits with 130 or 143
  when interrupted, after rolling back. The TUI pairing helper exits with 75
  when pairing needs the owner's attention; the installation itself still
  completes, and pairing has to be run afterwards with the printed command.
- **Install locks.** A lock directory created by an older version has no owner
  record. If one was left behind, the installer refuses it and prints the
  `rmdir` command to run once you have confirmed that no install or uninstall
  is running.
- **Actions that are now refused.** Answering or closing a closed query;
  publishing a published packet; cancelling a finished workflow; resetting a
  running, fired or cancelled trigger; retrying a completed agent task through
  the daemon API (status 400); running a command in a stopped sandbox session;
  resolving an undelivered work proposal; queueing a channel draft that is
  already queued; `start` on a paused or blocked research run; `pause` on a
  planned or blocked research run; marking an unreviewed or rejected research
  source as used; reversing a decided document suggestion.
- **Actions that now leave the record unchanged.** Cancelling a fired or
  cancelled trigger, and rejecting a pair request that is already verified,
  expired or rejected. The pair request is returned with its actual status.
- **ACP.** A hosted agent whose turn was cancelled is now `idle`, not
  `stopped`. A subagent run emits a single terminal event.
- **Realtime transport.** A connector that has reached `failed` no longer
  emits `disconnected` when it is disposed. Code that waited for a final
  `disconnected` after a failure should treat `failed` as final.
- **Voice.** Errors from releasing the audio stream during a wake-listener or
  push-to-talk stop are delivered to the failure callback and no longer reject
  the stop call.
- **MCP.** A stdio server that keeps exiting before it completes negotiation
  is left disconnected after three restart attempts instead of being restarted
  indefinitely.
- **Follow-ups.** A follow-up that fails five delivery attempts is dropped
  with a notice.
- **Relay.** A relay connection that has not registered within 15 seconds is
  closed and retried. Set `registrationTimeoutMs` to change the deadline.
- **Knowledge.** After upgrading, job runs that have been `queued` or
  `running` for more than six hours appear as `failed` with an "interrupted"
  error.
- **Agent exit.** Agent shutdown is bounded at 10 seconds. If it does not
  finish, the session is restored from its recovery snapshot on the next
  launch.
- **SDK.** See the changed and removed exports above. Code that passes plain
  strings to `closeModalByName` or `reopenModalByName` must narrow them with
  `isModalName` first.

## For contributors

- **Test runner.** `packages/engine/scripts/test.ts` is now one small runner
  shared by the engine and the products. Each run gets its own temporary
  directory, `--partition=I/N` selects a slice of the engine suite and
  `--jobs=N` (or `--jobs=auto`) runs files in parallel, one process per file.
  Test runs no longer take a repository-wide lock, and the watchdog, ceiling
  and temp-registry layers are gone.
- **CI.** The push workflow runs about 40 jobs instead of about 106, and the
  repository has 9 workflows instead of 17. The diagnostic and one-off
  verification workflows, their scripts and the unused reusable workflows were
  removed. The Bun version is read from `engines.bun` in the root
  `package.json`.
- **Recorded readings.** About 65 MB of recorded "readings" fixtures and the
  scripts that consumed them were deleted. `internal-id:check`,
  `credential-scope:check` and `error:check` are now plain rule checks with no
  stored state. The root scripts `todo:check`, `types:resolution-check` and
  the `*:read` scripts were removed.
- **Release tooling.** Release preparation and tagging steps now check their
  inputs before changing anything and print the command to resume or abandon
  when a later step fails. The engine publish order puts the judgment package
  first.
