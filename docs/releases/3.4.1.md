# GoodVibes 3.4.1

GoodVibes 3.4.1 removes the suggested prompts from the start screen of the
terminal app and the Agent. It also carries a long list of corrections across
every product: places where a step could run twice, report a success it did
not have, lose a value, or let through something that should have asked.

The changes most people will notice: the permission rules now read shell
scripts, grouped commands and commands built at run time; a stored setting no
longer stops a program from starting (an unreadable safety setting is held at
its strictest value instead, and you are told once); plugin trust covers every
file of a plugin; and times typed for a schedule are read in your time zone.

## Upgrading from 3.4.0

**What you may have to do**

- **Check a plugin you trusted whose files changed since.** A plugin's trust
  tier now covers every file in its folder, not just its manifest and entry
  file. A tier set under 3.4.0 is carried forward when the plugin is still in
  the folder it was trusted in and its manifest and entry file are still what
  you trusted (an untrusted record or a quarantine is left as it is); any other
  plugin starts untrusted
  and `/plugin list` says its tier was set for files that have since changed.
  Set it again with `/plugin trust <plugin> <tier>`.
- **Fix any setting a "could not be read" notice names.** A stored value of a
  safety setting that no longer reads as valid holds its feature at the
  strictest value until you fix it (see [Settings](#settings)). The one most
  likely to appear: an entry of `payments.majorRetailersAdditional` or
  `payments.majorRetailersExcluded` that names no shop (`foo`, `co.uk`), which
  3.4.0 accepted. While the exclusion list holds such an entry, every purchase
  asks you first.
- **Fix a per-tool permission a "could not be read" notice names.** A stored
  `permissions.tools.<tool>` that cannot be read now holds that tool at `deny`
  (every call of it is refused) until it is fixed, instead of asking.
- **Fix the hooks file if a hook stops loading.** A hooks-file entry that 3.4.1
  refuses is not loaded: an `async` hook under a point that waits for its hooks
  to deny, ask or rewrite a call (move it under a `Post` or `Fail` point, or
  remove `async`), and a chain step whose `within` or `debounce` is not a
  duration such as `500ms`, `30s`, `5m` or `1h`. You are told once per entry,
  with the file and the reason; the rest of the file loads, and the file is
  left as it is. `/startup review` also shows a `hooks` line with the reason.
- **Rename a custom provider whose name holds `:` or a space.** Its file is not
  loaded, because models are addressed as `name:model`. You are told once which
  file, with a suggested name; rename the provider in the file (for example
  `my llm` to `my-llm`) and change any model setting that named
  `my llm:<model>`. The file is left as it is, and every other provider loads.
- **Store an Azure remote backend's credential as a service principal.** An
  Azure remote backend registered with a credential that is not a service
  principal stays registered but refuses every command
  (`REMOTE_BACKEND_INVALID_CONFIG`). The daemon says so once on its first
  start, naming the backend and the secret reference: store the credential
  under the same reference as a JSON object `{"clientId", "tenantId",
  "certificate"}` (the service principal's application id, its tenant id, and
  a PEM holding its certificate and private key). Each command signs the Azure
  CLI in as that principal in a private config folder; the daemon user's own
  `az login` is no longer used. Every other backend runs as before.
- **Scripts that give both `--yolo` and `--just-vibes`** are now refused (exit
  `2`) instead of the later flag silently winning: they ask for different
  permission modes. `--yolo and --just-vibes ask for different modes (yolo and
  just-vibes) and cannot be used together: drop --just-vibes to run in yolo, or
  drop --yolo to run in just-vibes.` `--yolo --no-worries-just-vibes` (two
  spellings of yolo) is still accepted.
- **Clients of `email.attachment.get`** must send `uidValidity` (see [For
  client authors](#for-client-authors)).

**What the first start does by itself, and says once**

- Carries plugin trust forward (above) and says: "Plugin trust carried forward
  from the earlier version for N plugins (names); each is now bound to its
  current content, so a later change to any of its files needs /plugin trust
  again."
- For each stored safety setting that does not read as valid, says: "Setting
  <key> could not be read (<file>): it <why>. Fix it with /settings or in
  <file>; until it is fixed, <what is held>." For the retailer exclusion list
  the last part reads "every purchase asks you first". The notice is withdrawn
  once the value is fixed.
- For each custom provider file, hooks-file entry or Azure remote backend it
  leaves out (above), says which one, why, and what to change; the notice is
  withdrawn once the entry is fixed.
- Reads every stored knowledge extraction once more from its kept copy, so
  spreadsheets get their shared text and sheet names right. Rewrites each Home
  Graph snapshot node once at the first sync (one revision each).
- Reopens a feature-gap issue that 3.4.0 marked resolved without your review,
  when its gap is active again.
- Removes snapshot staging files a stopped 3.4.0 process left beside a store.
- Rewrites the daemon's Windows logon task at the next install or update (its
  quoting changed), since the old one no longer matches.

**What does not survive a rollback to 3.4.0**

Everything 3.4.0 wrote is read by 3.4.1. Going back to 3.4.0 starts on the
same data, with these losses:

- **Plugin trust** set or carried forward by 3.4.1 does not match 3.4.0's
  check, so those plugins need `/plugin trust` again on 3.4.0.
- **Push device removals still waiting** to reach the other machines of a group
  (in the push subscription file) are dropped by 3.4.0's next write, and 3.4.0
  serves those devices again until they are removed again. The same holds for
  the devices of a user who lost admin access while the group's authority
  record could not be read.
- **A memory class** that 3.4.1 refiled against a 3.4.0 memory host is ignored
  there; the record only leaves the pending state.
- **Settings import undo (Agent):** 3.4.0 replaces the list of earlier imports
  with a single one at its next import.
- **The Agent's hosted hand-off record** reads as empty in 3.4.0, which finds
  its hosted sessions again through the daemon.
- **Native hosted turn claims** written by 3.4.1 are not recognised by 3.4.0,
  which treats them as unproven.
- **A schedule whose last run was `partly-delivered`** shows no outcome words in
  3.4.0 until its next run.

## The start screen

- **The "Try one of these" suggestions under the logo are gone.** The three
  prompts that were offered for the working folder are no longer drawn, in the
  terminal app and the Agent alike. Tab in an empty composer and a click on a
  suggestion no longer put one in the composer; Tab does what it does
  everywhere else. Nothing else on the screen moved: the logo, the model and
  folder lines and the key hints are where they were.

## Talking to the model and approvals

- **Never-run rules, owner-only deletions and new-recipient asks read the
  whole command.** They now see through the shell's own keywords and grouping
  (`if … then git push; fi`, `while … do`, `{ … }`, `( … )`, `! git push`),
  comments (`git status # push` no longer matches a `git push` rule), shell
  options (`bash -o pipefail script.sh`), `bash < script.sh`, and a `cd` or
  `pushd` into a folder before a script runs. git's global options written
  without `=` are skipped: `git --work-tree /repo reset --hard` is a deletion.
- **A script that cannot be read counts against you, not for you.** A missing
  script, one the command writes first, `curl … | sh`, or a relative script in
  a folder only known at run time: a never-run rule refuses it, a deletion asks
  the owner, a send asks about a new recipient. The reason reads "it runs the
  script <path>, which could not be read (it may not exist until the command
  runs), so what it runs cannot be checked", "it runs commands a shell reads
  from its standard input, so what it runs cannot be checked", or "it runs the
  script <path>, in a directory only known when the command runs, so what it
  runs cannot be checked".
- **Command text built at run time** is read as written: `sh -c "cd $DIR &&
  make"` reads `make`, and `bash -c "git $SUB"` is matched by its built
  argument. Where the program or script itself is built (`bash -c "$CMD"`,
  `eval "$X"`, `sh "$F"`, `source "$F"`) it is treated as unreadable: "it runs
  a command whose text is built when the command runs" or "it runs the script
  <path>, whose path is built when the command runs".
- **A command's script is read where the command runs.** An exec call's own
  `cwd` (or `working_dir`) decides which `./release.sh` is checked.
- `mail -t`, `mailx -t`, `s-nail -t` and `sendmail -bs` or `-bS` are sends whose
  recipients cannot be read, so they ask about a new recipient. A host written
  with a trailing dot (`api.telegram.org.`) is read as the same host.
- **Hooks decide by rank: deny, then ask, then allow.** A `Pre` hook's `ask` is
  no longer cancelled by another hook's `allow`, and the first deny wins; the
  same holds when several chains complete on one event.
- A hook marked `"async": true` under a point that waits for its hooks to deny,
  ask or rewrite the call is not loaded: `hook is "async" but "<key>" is a
  point that waits for its hooks to deny, ask or rewrite the call; a background
  hook's answer would be discarded, so remove "async" (an observer belongs
  under a Post or Fail point)`.
- A chain whose step has an unreadable `within` or `debounce` is not
  registered: `chain "<name>" step <n>: "<value>" is not a duration (use 500ms,
  30s, 5m or 1h)`. An optional step with a debounce is skipped by an event for
  the next step, as one without a debounce is.
- A `once` hook loaded from the hooks file stays spent across reloads; editing
  it arms it again.
- `/hooks contracts` no longer prints `timeout=0ms` and ends with `Each hook
  runs under its own "timeout" (default 30 s, 60 s for an agent hook).`
  `/hooks enable` and `disable` list hooks only; a chain name is refused: `<name>
  is a chain; a chain cannot be switched on or off.` with `/hooks remove <name>
  takes it out of the hooks file`.
- The model's hook tool refuses when the hook it named changed while it waited
  for approval: `The hook "<name>" changed while this call waited for approval.
  Nothing was changed; list the hooks and ask again.`
- **Reviews are the owner's.** The model can no longer mark memory or notes
  reviewed (`OWNER_REVIEW_REQUIRED`, next step `Ask the owner to run /memory
  review <id> reviewed` or `/notes review <id>`), including through a command
  it runs; setting a memory's confidence names `/memory review <id> reviewed
  --confidence <0-100>`. Records the model marked reviewed earlier show
  `reviewed by agent` in the prompt.
- **Writes that replace a file ask for `--replace`.** `/services export`,
  `/security save-sandbox` and `/provider export` refuse an existing file (`<path>
  already exists; nothing was written.`) unless `--replace` is given. A
  model-run write outside the working directory is refused (`<path> is outside
  the working directory; nothing was written.`), and so is a model-run `/media`
  whose `--out` is outside the workspace.
- **`/services import` asks first**, in one question titled `Replace your
  services list with the one in <file>?` that lists each new or changed
  service. It is the owner's: run by the model, or with no way to ask, it is
  refused (`CONFIRMATION_REQUIRED`) with `Type /services import in the terminal
  app.`
- When an approved rule was saved but the approval itself could not be: `The
  rule you chose to remember is saved and in force, but the approval itself
  could not be saved (<reason>). The ask still shows as waiting; approve it
  again to record it.`
- Asks raised inside a program are cancelled when the daemon restarts
  (`requester-restarted`), instead of waiting for an answer nobody can act on.
  A device grant and its history entry name the principal who answered, not
  `operator`.
- In the terminal app, dismissing the folder-trust question with Esc records
  nothing; the call is refused and the next one asks again. Only "Keep
  restricted" records restricted.
- A policy bundle's `~/…` path patterns are read against your home folder.
  With no home folder known, the bundle is refused: `Not a policy bundle: rule
  N (path-scope) pathPattern "~/..." starts with ~, and no home directory is
  known here to expand it; write it as an absolute path.` When the active
  bundle's file cannot be read at start, `policy.bundlePath` is loaded in its
  place and the reason says so.
- Model references holding a colon resolve: `llama3.2:3b` on an
  OpenAI-compatible route, and `ollama` with `llama3:8b` as `ollama:llama3:8b`.
- OpenAI: a `400` about a request parameter no longer moves the request, or the
  model for the rest of the process, to the API key. When a refreshed
  subscription sign-in is still refused: `The OpenAI subscription sign-in was
  refreshed, but OpenAI still refused the request (status 401|403). <next step>
  OpenAI's answer: <message>`.
- A provider whose only sign-in is an expired, revoked or pending subscription
  shows `configured: no`. Bedrock without its optional package says "Install
  the optional @anthropic-ai/bedrock-sdk package to enable this provider."
- A failed turn's row counts commands that failed: "1 command ran before it
  stopped." instead of "Nothing was changed."
- `alt+o` on a failed turn resends only after a model is chosen and switched
  to; Esc and a later model change no longer resend it. In the Agent, choosing
  a model from `alt+o` now resends the prompt.
- Background work resumed after a restart shows only its outcomes. In a
  conversation whose turns run only on their host, it says: "[Background work]
  This work was not continued automatically: this conversation's turns run
  only on its host's permit. Send the request again from the host to continue
  it."
- **Reliability:** approval records are carried forward from an old
  `approvals.json` without duplicates after an interrupted run; per-session
  rules apply to nested and external tool calls; card-talk answers are kept per
  decision model.

## Channels, mail and notifications

- **Direct messages are judged as direct messages** on Slack, Discord, Google
  Chat, Matrix, Teams and Telegram, threads inside them included, by the
  channel's direct-message policy.
- A guest on a channel's allowlist is no longer treated as the owner; their
  sessions show as `unknown principal`.
- `channels.targets.resolve` with a name several conversations share returns
  the fallback target with `metadata.ambiguous` listing them, instead of one of
  them at random.
- Starting Telegram while it is switched off switches it on and says so:
  `Telegram is switched on (surfaces.telegram.enabled). Telegram receiving
  started: <reason>`, or that it is not receiving yet and why.
- WhatsApp in bridge mode counts as set up without a Meta access token; the
  token is the bridge's, needed only when the bridge asks for one.
- The generic webhook answers `400` `Invalid JSON body: expected a JSON object`
  for a JSON body that is not an object.
- A reply that could not be delivered because no target was known reports
  `not delivered` with the reason, instead of delivered.
- An ntfy topic whose stream is refused while this node leads is logged at
  error level ("ntfy is enabled but this node will NOT receive its messages")
  and is contested again later.
- Home Assistant: a repeat of a message id after a daemon restart answers from
  the transcript instead of posting again; two installations using the same id
  are separate messages; "Still working" always comes before the reply.
- **Mail drafts.** A save the server refused names why: "The draft was not
  saved: the mailbox is full.", "...: the Drafts folder '<name>' does not
  exist; set email.draftsMailbox to the name of the drafts folder.", "...: the
  draft is too large.", "...: the mail server refused it.", or "...: the save
  was cancelled before it was sent to the mail server." A draft replace whose
  answer was lost looks for the copy it may have saved before saving another.
- **Archiving or deleting mail on a server without MOVE.** When the copy
  landed but the original could not be removed: "The message was copied to
  '<target>' but is still in '<mailbox>' (marked deleted), so delete the
  original in your mail program instead of repeating the action." A message
  already marked deleted is removed only when its copy is found in the target;
  otherwise "Message n is already marked deleted in '<mailbox>' and no copy of
  it is in '<target>', so nothing was changed."
- Downloading an attachment checks the mailbox has not been reset since the
  message was listed: "The mailbox was reset since this message was listed, so
  nothing was downloaded. Refresh the list and try again." A message whose
  structure the server could not describe says so instead of "none at position
  k".
- A message whose body could not be fetched names the reason in
  `bodyUnavailable` (no text in the answer, several parts not fetched, not a
  text message).
- A mail user name, password or folder name that cannot be sent to an IMAP
  server (a line break, characters outside printable ASCII) is refused before
  the server is contacted, naming the setting to change. A folder that cannot
  be opened names `surfaces.email.imap.mailbox`; a refused sign-in names
  `surfaces.email.password`.
- Labelling a message read through the Gmail API: "This message was read
  through the Gmail API; labels are written to IMAP mailboxes only, so set
  this account up for IMAP to label it". Labelling many messages with one
  custom name no longer fails the others with "already pending".
- A mail verification wait whose expectation a newer one for the same address
  replaced answers `replaced`, naming the one to wait on.
- A held mail notice that is later refused reaches the owner inbox.
- **Calendar.** A Google create under the UID of an event that was deleted
  restores that event with what this create asked for; when Google holds the
  UID but returns no event, it fails `409` `CALENDAR_REQUEST_FAILED`: "Google
  refused event UID <uid> as taken but returns no event under it, so nothing
  was created. Create the event without a UID, or with a new one."
  `calendar.events.get` marks a deleted Google event `cancelled: true`.
- A CalDAV update keeps the organizer and the attendees it did not name, as
  stored. An event with `DURATION` and no `DTEND` gets its end. A CalDAV
  listing answered with something other than a CalDAV document says so.
- Google: when an app password was created but not read back, the fix says it
  cannot be recovered and must be deleted before running the step again.
  Registering a new OAuth client clears the old client's sign-in first.
- GitHub: when the agent ends without an answer, the issue gets "The agent
  ended <status> without an answer; mention me again to retry." CI check names,
  summaries and branches reach the agent as quoted untrusted text.
- Slack: a malformed token reads "surfaces.slack.botToken is not a Slack bot
  (xoxb-) or user (xoxp-) token, or it holds a space, line break or other
  character a token does not have; set it again"; with none stored,
  "surfaces.slack.botToken is not set; add a Slack bot or user token to read
  this inbox".
- A notification held back by a domain's verbosity is marked
  `domain_verbosity_low` instead of `allowed`. The model's notification
  summary marks a webhook target whose stored URL cannot be read as
  `unreadable`.
- Voice: an ElevenLabs voice id of `.` or `..` is refused; changing an
  unrelated setting no longer restarts a running local voice engine.
- **Reliability:** an owner alert for an approval is sent once; Discord resumes
  after a failed start; Matrix and BlueBubbles sends keep one identity across
  retries; route-binding updates list only the fields that changed; ntfy topic
  errors of removed topics are dropped.

## Schedules and background work

- **A time typed with `--at` is read in your zone.** `/schedule add|change --at
  2026-12-01T09:00` (and the web UI preview) reads the time in `--tz`, else
  your zone, not the daemon process's. A time with `Z` or an offset is that
  exact instant. Free-form dates ("Dec 1 2026 9:00") are refused: `Not kept:
  "<value>" is not a date and time. Use one such as 2026-12-01T09:00 (read in
  <zone> when it has no zone).` Described times go through `--when`.
- Cadences read exactly: "Every 90 s", "Every 90 min", not rounded.
- **A run delivered to some targets and not others** is `partly-delivered`
  ("delivered to some, not all"); the owner inbox gets "Delivered to some
  targets, not to <target> (<error>); ...".
- A failure or missed-run notice that reached no one is kept owed and sent at
  the next start. A failure follow-up reads the job as it is now, so a removed
  job stops it and a switched-off job is not switched back on.
- **Contracts.** A contract that cannot be resumed at start-up is left on disk:
  `Contract <id> could not be resumed at start-up (<error>). Now: contract <id>
  is left on disk unchanged. Next: See it with /agents contract <id>, then
  restart to try again. Or cancel it: goodvibes-contract cancel <id>.` When
  none could be: `[Contracts] Saved contracts could not be resumed at
  start-up: <reason>. They are still on disk; restart to try again, or /agents
  contracts-view to see them.` (the daemon keeps the same as a receipt).
- After a change you asked for was applied but the check against it could not
  run: "Your change was applied (<summary>), but checking the work against it
  could not run (<reason>); reply \"approve\" to run the check again,
  \"change: ...\" to change more, or stop the contract." After a pick that
  could not be merged: "The operator's pick of <attemptId> could not be merged
  (<reason>); say which attempt to take, or stop the contract."
- **Triggers.** An `http` probe is held to the fetch tool's host settings and
  refused at create with its reason (`TRIGGER_PROBE_HOST`, `422`); a probe's
  `timeoutMs` must be a positive whole number. A process limit note says "The
  same process (pid N, started at the same time) was still alive ...".
- **Occasions.** Removing one names the line to remove; a confirmed remove
  without it is refused ("Say which line to remove: ..."), and a repeat answers
  "That line of <id> is already gone; nothing more was removed." A title or
  person that would not read back as said is refused, and "me" without `self`
  is no longer stored as your own date.
- A workflow left an hour without a move is cancelled as abandoned whoever
  looks at it first: "Workflow <id> was cancelled as abandoned after an hour
  without a move; start a new one."
- CI watch: a repair that errors is tried again after its back-off; a refused
  one ends the watch with "CI repair not started". The poll summary counts
  repairs not started.
- A media job whose outputs could not be downloaded says "(<label> task <id>
  finished; its outputs could not be downloaded; collect it again with this
  task id)"; stopping a collect no longer cancels the job.
- Daemon task cancel or retry with a note: "The daemon keeps no note with its
  tasks, so your note was not saved."
- Orchestration: adding a dependency to an item that has started is refused
  ("item <title> has already started; a dependency added now would not hold
  it"); a phase with no recorded changed files is skipped; a worktree a cap
  eviction could not remove is reported kept. A hook condition with an
  unterminated string is refused at add time.
- Cloudflare batch queue: when the queue's spending coordinator cannot be reached,
  enqueue answers `503` `BUDGET_COORDINATOR_UNAVAILABLE` and nothing is
  queued; a redelivered job whose body was already taken reads `delivered`.
  When the queue's spending limit is reached, `/batch/tick/enqueue` names
  `/batch/tick` as the way to run it directly.
- **Reliability:** due runs and retries use the job as stored now; one notice
  per failed run; trigger stream counts survive a requeue; automation start
  failures are recorded on the job.

## Payments

- **Shop lists read shop domains.** `payments.majorRetailersAdditional` and
  `payments.majorRetailersExcluded` accept `www.shop.biz` and
  `https://shop.biz/...` and read them as `shop.biz`. An entry that names no
  shop is refused when set ("comma-separated shop domains, e.g.
  microcenter.com"); a stored one makes every purchase ask you first until it
  is fixed.
- **Sites on shared hosting are told apart.** The full public list of shared
  hosts is used, so `shop-a.weebly.com` and `alice.github.io` are each their
  own shop, not `weebly.com` or `github.io`.
- A refund or settlement note from shop mail that no channel took is sent at
  the next daemon start.
- `/payments add-card` that cannot start says so: `Card entry did not start:
  the selected daemon could not take a card (<why>). Nothing was asked or sent;
  run /payments add-card again once it can.`
- **Reliability:** card saves and removals run one at a time; a machine's
  group spend that could not be written is written again; a saved purchase
  question that cannot be settled at start stays pending and is logged.

## Knowledge and memory

- Bookmark import reads Chromium and Edge bookmark files (folders as `Bookmarks
  bar / Work`). Input with no http(s) bookmark is refused: `Bookmark input was
  read as <format>, but no http(s) bookmark was found in it; nothing was
  imported.`
- Spreadsheets: each shared string is read once, phonetic runs are left out,
  and sheets are named by their own tabs, in tab order.
- A Home Graph import holding records another knowledge space owns is refused
  whole, naming the record and the space. `shareWith` takes only `guest` or
  `all` (`HOMEGRAPH_REVIEW_SHARE_WITH`). A projection names its known
  dashboards (`source-health`, `backlinks`) and refuses any other.
- Knowledge activation without a decision model: "Knowledge activation held:
  serving knowledge without owner review needs a decision model, and none is
  in use. Set a decision model, or review the draft yourself."
- A batch import counts a failed re-fetch of an already indexed URL as failed,
  with an `errors` line for each failed URL.
- A feature gap that lost coverage after a repair is repaired again and its
  issue shows open. After a source is deleted, a node another source backs
  names that source as its owner.
- An answer with no deadline of its own ends synthesis after the configured 20
  seconds instead of waiting indefinitely.
- **The Agent's knowledge commands read files on your machine.** `ingest-file`
  uploads the file and names the path it read; `import-urls`,
  `import-bookmarks` and `ingest-connector --path` send the file's content. A
  file that cannot be read exits `1` (`file_unreadable`) with nothing sent;
  `--home` for a host on another machine exits `2` (`home_not_on_host`).
- `/memory restore latest` skips copies taken by a restore; when every copy is
  one: `Every memory copy was taken by a restore (<names>); name the one to
  restore in full. Nothing was changed.` (`MEMORY_SNAPSHOT_NOT_FOUND`).
- **Memory files.** Only fields edited in the file are proposed; a field memory
  changed since the files were written is never proposed back, and one both
  sides changed is listed and not taken (`/memory review-files` shows `...
  also changed in memory, so not taken (use /memory edit for the file's
  value)`; `/memory apply-files` reports it not applied).
- Memory search finds text and tags holding a backslash or a double quote. A
  stored summary with line breaks stays one line in the prompt. A plugin can no
  longer replace the built-in `hashed-local` embedding provider. The memory
  doctor says when Ollama or an OpenAI-compatible embedder runs on its built-in
  defaults and which variables change them.
- Skills: `skills active` lists what applies to turns (enabled or in an
  applied bundle, reviewed and ready). Deleting a skill removes a bundle left
  empty and puts one that keeps other skills back up for review.
- A document cannot be suggested or accepted under a title another document
  holds (`Document already exists <id>`). A research report whose run had
  already completed is attached to it, or saved on its own, and says which.
- **Reliability:** memory records refile in place; failed memory and kv writes
  are rolled back; snapshot copies are staged per process; record logs whose
  sync failed refuse further writes until a restart (`The log <path> had
  appended records that could not be synced to disk (<cause>); nothing more is
  written to it. Restart the daemon to open it again.`).

## Tools, MCP and plugins

- **Plugin trust covers the whole plugin.** A tier is bound to every file in
  the plugin's folder; changing any of them needs `/plugin trust` again. A
  folder with a file that cannot be read is refused: `Trust for '<name>' was
  not set: a file in <dir> cannot be read`. A trust change made while the
  shared trust file cannot be read is not saved. A plugin whose activate fails
  has its deactivate run; a failing event hook is logged.
- A plugin installed from a bundle keeps its grant in `.bundle-grant.json`
  inside its folder; a bundle member of that name is refused. An install that
  is refused or fails leaves the kept rollback points alone.
- **MCP.** A server that exits or fails its handshake shows its last lines of
  error output (`the server process exited unexpectedly: <lines>`). A server
  that keeps dropping is backed off, not counted as fresh each time.
  `/mcp trust` and `/mcp role` are kept in the MCP config. A call outside its
  scope under ask-on-risk is recorded as `ask`. The `/mcp` screens mask secret
  header values, URL passwords and secret query values.
- **One launched browser at a time.** A launch with another profile or headless
  setting while one is open is refused: `Session <id> uses profile <dir>
  (headless|with a window), and only one launched browser is open at a time,
  so it cannot serve a launch for profile <dir> (headless|with a window).` with
  `Close it with action:"close" (sessionId <id>) and launch again.`
- **exec with `until`** and no `kill_after` returns at the match and leaves the
  command running in the background, with its `process_id`. A background
  process whose output cannot be saved says so in its output: `[goodvibes:
  output could not be saved past this point (<reason>); later output is shown
  here only]`. The sandbox also hides git's credential store under
  `~/.config/git/credentials`.
- **read** refuses a file that is not UTF-8: `File is not valid UTF-8 text (it
  may use another encoding such as Latin-1 or Shift-JIS), so it was not read.
  Pass force_text: true ...`. Every result clipped by `max_tokens` is listed in
  `summary.truncated`.
- **inspect** refuses a path whose link leads outside the project, finds
  Next.js `app` and `pages` under `src/`, and lists `pages/api` index handlers
  at their folder path. **find** that stops at its time limit says how many
  files it checked. `goodvibes_context` refuses an unknown setting key ("No
  setting has that key. ...") and an unknown mode, naming the modes.
- Validators run under the call's limit (default 120 seconds): "Validator
  '<name>' timed out after <ms>ms and was killed".
- `work_plan` update clears owner or notes when given an empty string;
  `/todo edit` clears owner, notes or source with `-`.
- With `tools.autoHeal` off, edits make no repair attempt and give no warning.
- Model compare: a reference that matches nothing or more than one model is
  named; two references to one model run it once.
- **Reliability:** custom provider files load once at a time; a browser that
  failed to close keeps its card material; fetch drops a redirect's body;
  OpenRouter, LM Studio and Codex streams release their connections;
  local servers report their real caching.

## The daemon, updates and services

- **`goodvibes service install|start|restart`** exits `1` when the daemon
  command succeeded but the daemon never ran or answered; `--json` carries the
  same `ok` and `exitCode`.
- **`goodvibes-daemon install-service`** says `service is running; it does not
  start at login` when autostart is off, and a line for each setting it could
  not save.
- A daemon settings file that cannot be read (permissions, a folder) is no
  longer moved aside: setting a key fails with `<path> could not be read
  (<code>); fix or remove it, or start with --working-dir`. A file that is not
  JSON or not an object is still moved aside, and the log says which.
- **Settings import.** Credentials an import clears are deleted only after the
  settings themselves were saved; a deletion that does not complete leaves the
  receipt `partial`, naming it.
- **Cloudflare.** `/cloudflare disable` asks first and removes the Worker's
  daemon credential from the Secrets Store; when it cannot, it warns (`Could
  not remove the daemon credential <NAME> from Secrets Store <id>: <reason>.
  ...`) and reports `remote: 'not-disabled'`. Its last line says whether the
  operational token was revoked. A requested zone name is used even when a zone
  id is configured. A cloudflared that could not start reads "cloudflared could
  not start: <error>. It is started again in N s."
- The daemon page's approval buttons work, and a stale press shows `<url>
  refused: <reason>`.
- A WebSocket `call` frame that fails gets the HTTP answer the route gives; a
  bad method or a body on GET or HEAD is `400` `INVALID_ARGUMENT`.
- Outbound TLS in `custom` or `bundled+custom` mode refuses a request when a
  configured CA could not be loaded: `network.outboundTls.mode is custom, but a
  configured custom CA could not be loaded: <errors>. Fix the path or switch
  network.outboundTls.mode to bundled.`
- A hosted session file that cannot be read now (an I/O error) is left in place
  and tried again at the next start; only invalid JSON is moved aside.
- A failure of the capture sweep at start is a warning and the daemon starts.
- **Remote work.** `GET /api/remote/peers` returns every peer when no `limit`
  is given (it was the first 200) and takes `kind` and `limit`. Removing an ssh
  backend retires its pooled connections. A runner moved to another pool leaves
  the old one (the remote tool answers `movedFrom`). Task reads say when the
  daemon answered without tasks; an unknown daemon task reads as not found.
- **Reliability:** wake catch-up steps run even when one fails; Cloudflare
  provision and disable run one at a time; the daemon's Windows logon task is
  quoted correctly with environment values; telemetry is installed once.

## Pairing, devices and sign-in

- `goodvibes auth add-user` and every other way to add a user refuse a
  reserved name: `Username <name> has the reserved form "<form>", which another
  kind of credential signs in as; choose another name.`
- The terminal app's Paired Devices revoke says `Revoking "<name>"...`, then
  what was revoked with it, or `"<name>" was not revoked: <reason>`.
- A device token past the managed rotation age is refused on every machine of
  a group, and the token report gives the rotation age the store enforces.
- A pairing verify after another device took the same node id: `409`
  `REMOTE_PAIR_REPLACES_PEER`, nothing changed; pair again and confirm the
  replacement.
- A relay pairing string with no relay code is refused when it is pasted.
- Relay codes: a mint refused because the authority record cannot be read is
  `503` `AUTHORITY_RECORD_UNAVAILABLE` ("no relay code was issued and nothing
  was paired"); a revoke that cannot reach the record is `503`
  `RELAY_CODE_REVOKE_FAILED`, one not saved locally `500`
  `RELAY_CODE_REVOKE_NOT_SAVED`, each naming how many relay connections were
  closed.
- While the group's authority record cannot be read, push device changes and
  passkey registration or removal are refused ("The authority record <path>
  could not be read, so no credential change is written over it. Check the
  file, then try again.") instead of wiping the local list. A removed push
  device stops being served at once, even before the other machines hear of
  it.
- Cluster: `--key -`, `--passphrase -` and `--token -` read the value from
  standard input, and `cluster join` reads a piped key. A daemon's refusal is
  passed through with its code (`ADMIN_REQUIRED`), or names which credential
  was sent.
- `/auth inspect` shows the dialled daemon's sign-in address (`daemonLoginUrl`)
  or `no daemon address set`.
- OpenAI sign-in during setup says when its callback port could not be opened
  (`callback listener: unavailable (port 1455 could not be opened: <reason>)`)
  or was not used. A stored session with a new sign-in waiting shows only how
  to finish it.
- **Reliability:** a password sign-in that upgrades its stored hash keeps roles
  changed meanwhile; the companion token is never minted twice.

## Settings

- **A stored setting never stops a program from starting.** A safety setting
  whose stored value does not read as valid (it used to refuse the whole
  settings file) is held at its strictest value and you are told once (see
  [Upgrading](#upgrading-from-340)): `permissions.tools.*` refuses every call
  of that tool;
  `permissions.mode`, `policy.bundleSource` and `policy.bundlePath` ask as in
  Ask me; `permissions.engine` uses the policy engine; `policy.registryEnabled`,
  `policy.requireSignedBundles` and `relay.requireStepUpForMutations` are on;
  `judgment.fallbacks`, `judgment.backend`, `judgment.keyName` and
  `provider.decisionRouter` ask no decision model and ask you instead;
  `fetch.blockedHosts` refuses every website; `conversationGate.mode` confirms
  every step; `sandbox.mcpIsolation` runs MCP servers contained;
  `storage.secretPolicy` keeps secrets in secure storage only;
  `runtime.toolBudget.*` is enforced at its tightest; and an unreadable
  `payments.majorRetailersExcluded` makes every purchase ask. A new value that
  does not validate is still refused when you save it. Only a settings file
  that is not JSON, or one a newer release wrote, is refused.
- Changing `surfaces.email.host`, `surfaces.email.imap.host`,
  `surfaces.email.smtp.host` or `surfaces.msteams.serviceUrl` alone while a
  password is stored is refused (`CREDENTIAL_DESTINATION_UNBOUND`); a project
  file cannot set them.
- Writing a secret as plain text while a secure copy exists either removes the
  secure copy or refuses: `Secret KEY was not changed: the secure store at
  <path> cannot be read (...) ...`.
- A synced conflict on a credential cannot be resolved with the local value
  when it held a plain-text credential before the pull; resolve it with the
  incoming value or a `goodvibes://secrets/` reference.
- A setting a hosted client owns is checked like any other: `<key> was not
  changed: <reason>.`; a loosening the owner must approve reports `refused`
  with the owner's reason.
- The routing editor says when the settings changed elsewhere while it was
  open, and offers Edit again or Discard the edit.
- Presets carry display and behaviour settings, `provider.model` and
  `provider.reasoningEffort` only; other `provider.*` keys are shown as not
  applied. An unstorable preset name is "Profile not found: <name>".
- The voice picker for another provider sets the provider and the voice
  together ("TTS provider set to <p> and voice to <id>.").
- Clearing a saved relay URL or telemetry endpoint during setup now clears it.
  A failure to remove a subscription's stored tokens is shown.
- A service test answered with a redirect does not follow it: "<service> was
  reached and redirected (HTTP 302) to <location>; nothing was sent there. Set
  baseUrl or testPath to the final address".
- **Reliability:** routed daemon writes and refused writes keep the view in
  step; project secret and service approvals are merged under a lock.
