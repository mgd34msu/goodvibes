# GoodVibes 3.4.3

GoodVibes 3.4.3 fixes what goes wrong in a long working session that asks for
agents to be fanned out over a project. In 3.4.2 such a session could have its
agents refused again and again, lose finished contract work because the
decision model could not read a check, stamp every answer "Not verified", and
fill the screen with notices about work in progress.

Now: when you ask for agents, they start. A decision model that cannot answer
no longer ends a contract. A notice appears only when something needs you.

## Upgrading from 3.4.2

**What the first start does by itself, and says once**

- **Settings an earlier version left are carried forward.** A key only the
  daemon's settings file sets (for example the `service.*` keys) that is still
  in the terminal app's or the Agent's own settings file is moved to the
  daemon's file when that file does not set it, and taken out of the program's
  file either way. A key this release no longer has
  (`behavior.suggestAlternativeOnProviderFail`, `judgment.decisionDeadlineMs`
  and the others listed under [Settings](#settings)) is taken out, of the
  program's file and of the daemon's own file alike. Each file as it was is
  kept beside it first, as `<file>.before-3.4.3`, so no value you set is lost.
  A moved value is in effect for the daemon from this start: 3.4.2 ignored it
  in the program's file, so `service.autostart`, `service.restartOnFailure` or
  `service.logPath` set there long ago now change how the daemon's service is
  run (the daemon says so when it applies them). You are told once per file,
  in one line:

  `Settings an earlier version left in <file> were carried forward; moved to
  the daemon's settings (<daemon file>): <keys>; removed because the daemon's
  settings already set them: <keys>; removed because this version no longer
  has them: <keys>. The file as it was is kept as <file>.before-3.4.3.`

  (Only the parts that apply appear.) The seven `Setting service.* ignored`
  lines that 3.4.2 showed at every start are gone with them. A key this build
  does not know that no release had (a misspelling) stays in the file and is
  said once on this machine: `Setting <key> ignored (<file>): <why>.` (not
  again when 3.4.2 already said it).
- **Worktrees of contracts that ended are removed.** The start-up sweep removes
  every worktree whose contract has ended and that holds nothing of its own:
  no uncommitted or untracked change and no commit that is not in its base.
  A contract's own tree, its input snapshot tree and the unit trees inside it
  go together, the unit trees first. A tree with uncommitted work is kept and
  named once, with the commands to keep, save or discard it. What it removed
  is said once:

  `[Worktrees] Removed <n> worktree(s) whose work is all on a branch or in the
  base:` followed by one line per worktree.
- **The decision log is carried forward to a smaller form, in the
  background.** The first run of its background work starts ten seconds after
  start and moves 500 older rows at a time, with the program free to do
  anything else between them; nothing waits on it. Once the old entries have
  aged out under `atRest.retentionMaxAgeDays` (30 days unless you changed it)
  and what is left is small, the file is rewritten once and you are told how
  much space came back (each project's log and the daemon's own are carried;
  a log that gives back less than a megabyte is carried without a word):

  `[Decision log] The decision log was carried forward to its smaller form:
  <size> became <size>, so <size> came back to the disk.`
- **The Agent:** the reason a message runs in the Agent's own process (for
  example `No connected host is set up for this terminal, so messages run in
  this process.`) is said once on this machine, not at every session.

**Settings that are removed**

- `judgment.decisionDeadlineMs`: a decision no longer has a deadline of its
  own (see [Decisions](#the-decision-model)).
- `behavior.suggestAlternativeOnProviderFail`, `behavior.terminalNotifyTurnEnd`,
  `controlPlane.allowRemote`, the old `email.*` keys (`draftsMailbox`,
  `enabled`, `fromAddress`, `imapHost`, `imapPort`, `imapSecurity`, `mailbox`,
  `smtpHost`, `smtpPort`, `smtpSecurity`, `username`),
  `google.credentials.migratedFrom`, `notifications.burstCooldownMs`,
  `notifications.burstWindowMs`, `permissions.backgroundAgents`,
  `push.subscriptions.sweepIntervalMinutes`, `release.channel`,
  `sandbox.replIsolation`, `sandbox.vmBackend`, `sandbox.windowsMode`,
  `surfaces.email.imapHost`, `surfaces.email.imapPassword`,
  `surfaces.email.imapPort`, `surfaces.email.imapUser`,
  `surfaces.email.username` and `tools.contractVerification`: settings earlier
  releases had and this one does not read. They are taken out of any settings
  file that still holds them.

**What does not survive a rollback to 3.4.2**

Going back to 3.4.2 starts on the same data, with these differences:

- **The decision log.** 3.4.2 cannot read a decision log 3.4.3 has opened
  (each project's and the daemon's own), even before its rows were carried. It
  keeps the file aside and starts a new one, and says: `The record of past
  decisions could not be read (<reason>). It was kept at
  <path>/decisions.sqlite.unrecognized-1 and a new one was started.` Nothing is
  deleted.
- **Settings keys** that were moved or taken out stay that way; 3.4.2 reads the
  moved ones from the daemon's settings file, where it read them before, and
  did not use the removed ones. A moved value stays in effect under 3.4.2 too,
  although 3.4.2 ignored it before the upgrade; to undo it, set it again with
  `goodvibes-daemon config set` (the old value is in the `.before-3.4.3` copy).
  The copies kept as `<file>.before-3.4.3` are left where they are.
- **Worktrees** removed by 3.4.3 are gone; their branches held nothing extra.
  The `toldAt` mark 3.4.3 adds to a kept worktree in `worktrees.json` is
  ignored by 3.4.2, which names that worktree again at every start.
- **Contracts** 3.4.3 ran, the units it recorded as not judged included, are
  read by 3.4.2 as they are.

## Agents

- **When you ask for agents, they start.** Whether you allowed agents is read
  from everything you said in the conversation, oldest first, and the last
  thing you said about agents stands; a message that says nothing about
  agents (a question, a complaint, another request) changes nothing.
- **Plain code decides the plain cases, with no decision-model request:** you
  asked for agents (fan out, a set or team of agents, use, start or assign
  agents, delegate) and nothing later forbade them: they start. You named a
  number and the call starts no more: they start. You forbade them in plain
  words (`do not use agents`, `don't delegate`, `no agents`, `do it yourself`)
  and asked for none later: the call is refused.
- **What plain code cannot settle goes to the decision model in one small
  request**, once per state of the conversation: you said nothing about agents,
  one message both asks for and limits them, or the call starts more than a
  number you named.
- **When the decision model cannot answer**, the permission mode decides:
  `yolo` and `just-vibes` start the agents; `ask-me` and `jev-decides` ask you
  once, with the tasks and the reason (`Nothing you said in this conversation
  asks for or rules out agents, and the decision model could not read it
  (<why>). Start <n> agents to do the work listed? Your answer stands for the
  rest of this conversation.`), and your answer stands for the conversation;
  under `Decision Model Only` the call is refused and says what would be
  accepted; plan mode starts nothing.
- **A refusal quotes your words and is never cut short:** `Not started: the
  owner said "<your words>", and no later message of the owner asked for
  agents. This call would start <n> agents. Accepted instead: <what>`. A
  refused plan is no longer held, and the model is no longer told not to try a
  contract instead.
- **The same refused call is not sent again.** The model is told once more, in
  full, that this exact call was refused, and you see one line:
  `[Blocked] <tool> was asked for again exactly as before and was not run:
  <reason>`.
- **A contract started for agents is titled with the work you asked for**,
  followed by the planned tasks, never with your latest message.
- **After a crash, the model can ask what its agents did in one call:** the
  `agent` tool's new mode `activity` returns each contract of the session
  (state, units, answers) and each agent it or the session started: its state
  (including `cut off` when its run never ended), the files it read, whole or by
  line range, the files it changed, the commands it ran and its last report.
  `status`, `get` and `wait` on an agent that no longer runs say what it was and
  what its contract is now, never a bare `Unknown agent`.

## Contracts

- **A decision model that cannot answer no longer ends a contract.** Every
  check a contract asks of the decision model has a fallback: when the model
  fails, does not answer or refuses the request, the check is decided by code,
  the unit is recorded as not judged with the reason, its work is kept as
  delivered and the contract goes on. A contract fails only when its work
  failed. This holds under `Decision Model Only` too. You see one line per
  contract: `[Contract] <id>: the decision model could not judge part of this
  work (<reason>); that work is kept as delivered and the contract goes on. Its
  result lists what was not judged.` (or only the decision model's own failure
  notice, when that already said it). The result lists `Judged and passed: …`,
  `Delivered but not judged: …`, `Not delivered: …` and where the work is.
- **Requests to the decision model fit what it accepts.** Every request is sized
  to what each configured decision target reads in one request. A larger one is
  split by question, and each question that does not fit beside the whole
  evidence is asked with the parts of the evidence most related to it; each
  part left out is marked where it was. A contract check no longer carries
  other units' full command output.
- **Contract gates run only for what a unit changed.** `typecheck` runs for a
  changed script source or TypeScript or project configuration, `lint` for a
  changed script source or ESLint or project configuration, any other gate for
  any changed file. A unit that changed nothing runs no gate. A skipped gate is
  shown as skipped, never with a failure mark.
- **In a worktree, the project's dependencies are linked in**, so a contract
  gate runs the project's own scripts as they run in the project. The links go
  in a `node_modules` folder git ignores, so they never show as a change or
  reach a commit. When there is nothing to link, the gate is reported once as
  `could not run here` and nothing is asked of the unit.
- **A contract no model can be routed to plan waits instead of failing.** It
  keeps its state and says once, to you and on its row, where its session's
  model reads it: `Contract <id> is waiting: no model can be routed to plan it
  (<why>). It plans on its own as soon as a provider that serves this work is
  available: signed in, configured, or answering again. Cancel the contract to
  stop it.` It plans as soon as the providers or their models change or a
  provider is answering again.
- **After a crash, a running contract is found and reported:** `[Contracts]
  Contract <id> ("<goal>") was running when the app stopped. It was found on
  disk and continues <step>; <k> of <n> unit(s) had finished (<units>); their
  results are kept in the contract. /agents shows it.`, or that it did not
  continue, why, and how to go on. The model of that contract's session is told
  the same line with its next request.
- **A contract held at start is said, not only logged:** `[Contracts] Contract
  <id> ("<goal>") was running when the app stopped and is held, not continued:
  <what could not be restored>. ... To go on: <what to do>.` Its input is
  checked by content and path (the recorded commit and files at the recorded
  folder), never by inode numbers, so a project folder copied, moved back or
  restored from a backup resumes.
- A resumed contract's planner agents no longer each add a `[Background work]
  ... nothing was run again` notice; the contract's own line says what it does.
- **Worktrees are released when their contract ends, however it ends:** the
  contract's tree, its input snapshot tree and every unit tree inside it, with
  branches that hold nothing extra. A tree holding uncommitted work is kept and
  named once.
- An unchanged plan is not checked again, and a plan the decision model could
  not read goes ahead marked as not independently checked.

## The decision model

- **The decision deadline and its setting are removed.** A request to the
  decision model ends when the server answers, answers with an error, or the
  connection fails. `judgment.decisionDeadlineMs` (1.5 s by default) cut off
  decisions that would have answered and reported the model as failing.
- `judgment.timeoutMs` stays, for what only it can notice: one attempt at one
  target that has had no answer for that long (30 s by default) counts as that
  target not answering, so the next target or the decision's own fallback is
  used. The decision API sends its whole answer at once, so nothing else tells
  a server that took the request and stalled, or a connection lost without a
  reset, from a slow answer. Raise it for a slow local model.
- A failing decision model is said once per outage, in one sentence, and the
  notice is withdrawn when it answers again: `[Decision model] The decision
  model <model> is not answering (<what failed>), so work continues without it
  until it answers again; to fix it, <next step>.` With no decision model set,
  nothing is said.
- **A decision model that cannot answer never ends a turn.** Whatever the
  reason it gives no usable answer (a request too large for it even after
  splitting, an HTTP error of any status, a malformed answer, a closed
  connection, an attempt with no answer), the decision takes its fallback, the
  reason is kept in the decision log, and the outage is said once in the line
  above. In 3.4.2 a model that refused requests as too large ended every turn
  that ran a tool call. Under `Decision Model Only` the one tool call it cannot
  decide is refused with the reason and the turn goes on.
- **The decision log stores each question set once** and gives space back to
  the disk a few megabytes at a time. A row is under a kilobyte on average
  (it was 3.5 KB, up to 49 KB). Entries older than `atRest.retentionMaxAgeDays`
  are removed.

## What you see

- **Notices only when something needs you.** A notice is something that needs
  your answer, something you asked for that finished or failed and the answer
  does not already say, or something of yours that was changed or skipped.
  Progress of work in flight is shown on the work's own row (the turn's row,
  the agents view F2) and in the activity log.
- **No longer shown:** contract starts and state changes, contract gate and
  check lines, nudges, a contract that succeeded or was cancelled (its
  follow-up answer reports it), `[Agents] A contract started …`, `[Delegated
  work] … The results were given to the model.`, the host's `Runtime reference
  data` message drawn as if you had typed it, `[Tool recovery] N tool rounds in
  a row failed …`, `[Response cancelled]`, `Decision Router: …` on every routed
  turn, `[Session] Auto-titled …`, `[TTS] Live playback queued …`, `Previous
  session found` and `Workspace history found` at every start, `[Update] This
  copy of GoodVibes runs from its source folder` at every start, the routine
  `[MCP]`, `[Scan]`, `[Local]` and `[Calendar]` lines, `[Workspace]
  Registered/Not registered`, and context-usage and auto-compaction progress
  lines.
- **Where contract and agent progress shows now:** on the work's row and in
  F2, and in the activity log (`[Contract] <id> started: …`, `<id> <from> ->
  <to>`, `Gate: …`, `Check …`, `Nudged unit …`).
- **No "Not verified" line after ordinary answers.** The completion check that
  held every answer up to 30 s is gone. Only after a turn that handed the model
  the results of agents or a contract is the answer read once more, after it is
  shown and without delaying anything, and a line appears only when it claims
  work its agents or contract did not do: `[Check] The answer above says work
  was done that its agents or contract did not do or did not finish; F2 shows
  what each one did.`
- `No GoodVibes daemon is running and none is installed` is said once on this
  machine, and again only after a daemon was found and then lost.
- A failed automatic compaction is said once, in its `[Compaction]` line, with
  what happens to the request and what to do.
- When the terminal app moves your routines to the daemon, it says so, and
  warns when some could not be moved.
- Background work resumed after a restart is reported by its follow-up answer;
  when it is not continued, the line names the work.
- The model is handed each agent's final result once; a later turn no longer
  repeats agents from earlier turns.

## Tools

- **`find` honours ignore files.** Content, symbol, structural and reference
  searches apply `.gitignore` and `.ignore` at every level, say how many files
  they left out, and do not walk into `.goodvibes` unless it is named; a file
  listing applies the root ones, as before, and says when nested ones exist.
  It has no fixed time limit: a search ends when it is done or cancelled. A
  caller's `timeout_ms` is a budget that returns what was found, marked as
  partial (`Stopped at the time budget … results may be incomplete`). Inside a
  contract's read view, an ignore file the view may not read is left out and
  the result says so, instead of the search failing.
- **A provider is no longer held out of routing because its model list could
  not be read.** Only a listing failure that says calls fail too
  (authentication, authorization, billing, network, timeout, a server error)
  holds it out; a `400` or `404` from the listing, or an empty list, does not.
- **Memory held per compaction.** A compaction archives only the messages it
  removed, not a copy of the whole conversation, in every agent and in the main
  conversation.

## Settings

- Removed: `judgment.decisionDeadlineMs`, and the keys listed under
  [Upgrading](#upgrading-from-342).
- `judgment.timeoutMs` describes what it is for (see [The decision
  model](#the-decision-model)).
- `atRest.retentionMaxAgeDays` also covers the decision log.

  the decision model could not judge it.
