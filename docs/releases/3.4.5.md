# GoodVibes 3.4.5

GoodVibes 3.4.5 answers three outside reviews of the interface. It says what is
in force before what you chose, names things for what they do, keeps one Google
connection for the Agent, the daemon and the web app, and refuses to print a
pairing code a phone could not open. The web app is easier to read and to use on
a phone. An ordinary turn costs what it cost before.

## Upgrading

- **All programs must be on 3.4.5 for pairing.** The daemon's pairing answers
  gained a field (`reach`) that a 3.4.4 program refuses to read, so pair with a
  terminal app, Agent and web app of the same release as the daemon. The
  installer and the updater install them together.
- **Your Google calendar connection moves once.** A Google account connected
  with the Agent's `/calendar connect google` was kept apart from the one the
  daemon uses, so the web Calendar never saw it. The daemon's first start of
  3.4.5 moves it into the one Google connection and says, once, "Carried
  forward from the earlier version: 1 Google connection." When the daemon
  already had a different Google account, that one stays, the other is kept
  unused, and the notice names both and how to choose the other.
- **Going back to 3.4.4.** 3.4.4 starts normally on a home 3.4.5 has started.
  If you go back to 3.4.4 after 3.4.5 has started once, the web Calendar and the
  daemon's calendar and mail keep your Google connection, but the Agent's
  `/calendar accounts` lists no Google account, because 3.4.5 moved the
  connection made with `/calendar connect google` into the one Google
  connection that 3.4.4's `/calendar` does not read. Run
  `/calendar connect google` in the Agent to use it there again. A Google
  sign-in made with an OAuth client that has no client secret works with the
  3.4.5 daemon only.

## When GoodVibes asks

- **The status bar leads with what is in force.** It used to read
  `Asks: Jev decides · asking you for now · no decision model set`. Now it
  reads `Asks: you, for now · Jev decides once a decision model is set`: what
  happens now first, then your choice and when it takes effect, and a failure
  (such as `decision model unreachable`) last. The web app's header chip says
  the same words.
- **One name for the choice:** "When GoodVibes asks", in settings, the Agent
  workspace, the command palette and the `Shift+Tab` help. The status bar keeps
  `Asks:` as its short form.
- **Trusting a folder says what it does.** The trust prompt no longer says
  "Full capability: all tools may run". Trusting a folder lets its own hooks
  and MCP servers run and lets GoodVibes change files in it; it approves
  nothing, and each action still follows your setting for when GoodVibes asks.
- **Remember options run narrow to broad.** "Any command in this project" comes
  last and shows on its own line what it covers: whatever it names, until you
  remove the rule. Enter still never remembers.

## Terminal app and Agent

- **`--help` starts with the commands most people run:** start, run one
  prompt, pair a phone, check status and check for an update, then the full
  list.
- **The command palette** counts the same rows in both of its numbers, and no
  longer repeats a command's summary as its action.
- **A failed daemon command names itself first:**
  `goodvibes-daemon webui enable failed`, then `Reason:` and `Next:`.
- **The model picker** names each tab for its job: Main chat, Side work, Tool
  work, Spoken replies, Decision model and Search index. Each tab lists only
  models the catalog says read and write text, so an image, video or speech
  model is not offered for chat; a model the catalog does not describe is
  listed after the others, marked `kind unknown`.
- **Set the decision model where models are set.** The new Decision model tab
  sets and clears it with the same steps as Settings, and the status bar's
  "once a decision model is set" goes away and comes back with it.
- **The Agent workspace** puts everyday work first and setup after, names its
  groups and areas for the job (Inbox & calendar, How it talks, Procedures,
  Saved workflows, Schedules, Agent homes), shows the slash command that opens
  each area, and shows the Agent home and account in its title. A non-default
  Agent home is named in the status bar. A report says when it was read, and
  "not read yet", "reading…", "nothing to show" and "could not read" are told
  apart.
- **First start of the Agent** on a computer where the terminal app has
  settings says once that `/setup import-settings` brings them over.

## Pairing a phone

- **No code a phone cannot open.** `goodvibes pair`, `goodvibes-agent pair`,
  `/devices pair device`, `goodvibes-daemon pair` and the web app's Pair a new
  device first ask the daemon whether another device could reach the address
  in the code. When the daemon serves only this machine, nothing is made: the
  answer says why and gives the one command that fixes it,
  `goodvibes-daemon webui enable --lan`. `goodvibes pair` then exits 1.
- **Every pairing answer is one numbered list** of what is done and what is
  next.

## Calendar and Google

- **One Google connection** serves the daemon's calendar (the web Calendar),
  its Gmail access, `/google` and the Agent's `/calendar`. Every Google sign-in
  asks for the same scopes, `calendar.readonly` included; a connection made
  earlier with fewer works for what it has and names what is missing when a
  feature needs it.
- **When the web Calendar has nothing to read** it says which accounts exist
  and why none can be read, under the title "No calendar this daemon can read".
- **The web Calendar** shows each event from start to end, names the time zone
  once, picks dates as Today, This week, Next two weeks or This month, and
  names each calendar.

## Web app

- **Easier to read.** Muted text now reaches at least 4.5:1 contrast on every
  background, in the dark and light themes.
- **The composer's model is this chat's.** Picking a model or effort in a new
  chat sets it for that chat; the default for new chats is changed in Settings.
- **Send while a reply runs.** The button says Queue (it sends after this
  reply), and a visible Send now interrupts. Holding the button still
  interrupts.
- **An unknown `/command` is not sent.** The composer says it is not a command
  here, points to `/new` and `Ctrl+K`, and keeps your text. A path such as
  `/etc/hosts` is still sent.
- **Starting points** for calendar and mail show only when that account is
  connected.
- **Settings search** matches every word you type, in any order.
- **An expired provider sign-in** has a Sign in again button on its row that
  copies the terminal command which signs it in again.
- **Memory** says what a record's rating is: how sure it is said to be, who
  set it, and that records below the recall floor are not brought into
  answers. Each scope says where it applies, and each filter sits under the
  question it answers.
- **Files in this chat** lists every file the chat produced, newest first, each
  linking to its message. Code blocks have a wrap button, remembered on the
  device.
- **On a phone**, each message shows Copy and keeps the rest under More, a
  banner says when something in another chat waits for you, and a long chat
  title is cut short instead of pushing the header chip aside.
- **A pinned sidebar stays open** beside a detail wherever both fit, and says
  so on the pin when the window is too narrow.
