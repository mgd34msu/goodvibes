# GoodVibes 3.4.7

GoodVibes 3.4.7 places the web app's model menu beside its control and inside
the window, shows a short list of recommended models in every model picker,
names the approval that remembers your answer for what it does, asks how
purchases should run when payments are turned on, lets you type straight out
of the Agent workspace and come back, makes the terminal's dim text readable in
every built-in theme, says when a channel reply was shortened, and keeps the
installed web app in one folder with one previous copy. An ordinary turn costs
what it cost before.

## Upgrading

- **All programs must be on 3.4.7.** The daemon's model list answer
  (`models.list`) gained a field (`recommended`) that a 3.4.6 program refuses
  to read. The installer and the updater install them together.
- **The model catalog is read again once.** The catalog kept on disk now holds
  each model's release date. A catalog saved by 3.4.6 is used at once and
  checked again in full in the background. 3.4.6 started on a home 3.4.7 has
  started reads its catalog again the same way.
- **The web app's folder is renamed on the daemon's first start.** See
  [The installed web app](#the-installed-web-app).

## The model menu in the web app

The menu under the message box opened wherever the page put it: on a short
window it covered the message box or ran under the header, and a long list
pushed it off the screen. It now:

- sits beside its control with a small gap, on the side with more room, and is
  never taller than that room; only the list scrolls, the filter box and the
  footer stay put;
- keeps its place while you move between provider, model and effort, and
  places itself again when the window is resized or a phone's on-screen
  keyboard changes the page;
- shows a fade at the list's edge when a row is cut by it;
- opens as a panel in the middle of the window, over a dimmed page and below
  the header, when neither side has room for the filter box, six rows and the
  footer (a 600-pixel-high window, for example). Escape or a click outside
  closes it, and focus goes back to the model control;
- stays a bottom sheet on a phone, with the header still visible.

Its footer says one thing: "This is the default for new chats." when the model
picked is the default, otherwise "For this chat only." with the button "Make
this the default for new chats".

## Recommended models

Every model picker (the terminal app's, the Agent's and the web app's model
step) shows up to five models under **Recommended**, each with why, taken only
from what the model catalog says about the provider's models:

- `newest <family>`: the latest release in its family;
- `largest context: 1M tokens`: the largest context window the provider offers;
- `lowest price: $0.15 in, $0.60 out per 1M tokens`: the cheapest to use.

A model can have more than one reason ("newest bulk, largest context: 200K
tokens"). Pinned and recent models stay above the list and are not repeated in
it. When the catalog gives no release dates, context windows or prices for a
provider, no Recommended group is shown. For programs, `models.list` carries
`recommended` (the why) on those models, only for providers that are connected.

The daemon did not load the model catalog when it ran on its own (as a
service): every model it listed was "kind unknown" in the web app's model menu.
It now loads the catalog when it starts and
checks it once a day, as the terminal programs do.

## Approvals that remember

The approval button and key that make a rule read **Yes, and remember (choose
what)** (it was "Yes, and don't ask again…"), and the key hint reads `a
remember`. It opens the same list as before: this exact command, any command
of that kind for this session only, in this project, or any command in this
project. The words come from one place for the terminal app, the Agent and the
web app. Nothing about what is remembered changed.

## Turning payments on

Turning on "Let GoodVibes make purchases" (`payments.enabled`) now asks how
purchases run, in the terminal programs' Settings and in the web app's:

- **Ask me before every purchase**: Nothing is bought until you approve it,
  naming the shop, the item and the most it may cost.
- **Buy, and give me 10 minutes to stop it**: A purchase within your budgets at
  a shop you can get your money back from goes ahead unless you say stop within
  10 minutes; if the notice cannot reach you, it still goes ahead.

The number is your stop window (`payments.vetoWindowMinutes`). In the web app
"Turn on" stays disabled until one is picked; once on, the row reads "On:" with
the way chosen and its line. In the terminal programs the row opens a list with
Off and the two ways. The choice is saved as `payments.confirmEveryPurchase`,
as before; no default and no saved setting changed. A purchase whose notice
cannot be delivered still goes ahead, as in 3.4.6; the second line now says so.

## Typing in the Agent workspace

Typing a letter in the Agent workspace (`Ctrl+G`) still starts a message. The
footer of every area now says so: `a-z start a message, Esc there comes back
here`. Escape on text you have not sent brings you back to the area and row you
left. A single stray letter is dropped on the way back; anything longer stays in
the message box.

## Channel replies that are shortened

A reply or status line cut to fit a channel (Slack, Discord, Telegram, a
webhook and the others) ended in a bare `...`. It now says it was shortened:
a long reply ends with `[shortened: 337 characters not shown]`, a status line
cut to fit with `[shortened]`, and a work item's label with `(shortened)`.

## The installed web app

Updates left a web app folder named after an old version (`webui/3.3.1`
holding 3.4.6), one older copy per folder, and the lock files of every update.
The installed web app now lives in `webui/current`, with exactly one previous
copy in `webui/current.previous` for a rollback.

- The installer and the updater write `webui/current`; an update moves the
  copy it replaces to `current.previous` and removes the older one.
- On its first start after the update, the daemon renames the folder it serves
  to `current` (its previous copy to `current.previous`), points
  `controlPlane.webui.bundleDir` at it, removes other release folders the
  installer made and the lock files of folders that no longer exist. A folder
  without the installer's marker (your own build, for example) is left alone.
- `/update rollback` exchanges `current` and `current.previous`, as it
  exchanged the two copies before.

This was rehearsed on an install shaped like a 3.4.6 one (`webui/3.3.1`
holding 3.4.6 and served, `3.3.1.previous` holding 3.4.5, `3.3.0` and
`3.3.0.previous`, a folder of your own, and two finished lock files):
after the daemon's start it held `current` (3.4.6), `current.previous` (3.4.5)
and your folder; an update then left `current` (3.4.7) and
`current.previous` (3.4.6), and a rollback put 3.4.6 back in `current`.
