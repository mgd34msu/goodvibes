# GoodVibes 3.5.0

GoodVibes 3.5.0 takes more of the work of keeping it running off your hands.
First run gets a decision model working, a provider key already in your
environment is simply used, a command you typed or a form you submitted runs
without a second confirmation, the trust question comes only for a folder that
brings hooks or tool servers of its own, lists and screens read and refresh by
themselves, and a model that sends a malformed tool call is asked to send it
again instead of ending your turn. Requests that weaken a protection open on
No and say how long the change lasts. Editors can use GoodVibes over ACP, and
headless runs announce themselves.

## Upgrading

- **All programs must be on 3.5.0.** The daemon's answers for pairing changed
  shape; a terminal app, Agent or web app older than 3.5.0 cannot read them.
  The installer and the updater install every program together.
- **A daemon update downloads the whole suite.** When the daemon updates itself
  it downloads every program of the release (the daemon, the terminal app, the
  Agent, the web app and the browser driver), about 800 MB. On a slow
  connection that takes a while; `/update daemon` follows it to the end and
  never gives up on a slow download.
- **Keys that moved.** Switching between the session chips in the terminal
  programs is `Alt+N` (next) and `Alt+P` (previous); `Tab` and `Shift+Tab` no
  longer switch sessions. In the web app, "New chat" is `G` then `N` and
  "Toggle theme" is `G` then `T` (outside a text field); the browser kept
  `Ctrl+Shift+N` and `Ctrl+Shift+T` for itself.
- **Going back to 3.4.8.** Going back to 3.4.8 keeps your sessions, settings,
  memory, schedules, paired devices, providers and remembered permission rules:
  3.4.8 starts on a home this release has used. Three things this release keeps
  are not read by 3.4.8 and wait unused until you upgrade again: folders trusted
  automatically because they had nothing of their own to run (3.4.8 asks about
  them as new folders, the way it always did), the setup topics you skipped,
  and your answers to models that stopped being free. A remembered "This exact
  command" rule that 3.4.8 saved works for that command with or without a
  folder in this release; back on 3.4.8 it again matches only when the model
  names the folder the way it did when you saved it.

## Less for you to do

### First run gets a decision model working

GoodVibes ships set to "Jev decides", and Jev needs a decision model. When none
is usable yet, first run has one more step right after the model: **Who decides
when GoodVibes would otherwise stop and ask you?**

- **Jev decides**: paste your TypeSafe key. It is kept in the secret store and
  checked with one request; a refusal shows the decision model's own reason.
- **Another decision model…**: opens the decision-model settings (Cloudflare
  and the others), and comes back to first run once one is usable.
- **Ask me**: GoodVibes stops and asks you.

It is asked once and changed any time in `/settings` (When GoodVibes asks).
When a decision model is already usable, nothing is asked. Afterwards the status
line names the mode alone (`Permissions: Ask me`, `Permissions: Jev decides`).
Esc puts the question off, and it does not open again by itself: the status line
keeps saying what is in force and why (`Permissions: asking you, for now · Jev
decides: no decision model set`), and selecting that part of it opens the same
step. A home upgraded from 3.4.8 that is set to "Jev decides" with no decision
model is shown the step once, on its first start with this release.

### A provider key in your environment is simply used

When a usable provider key is in your environment (`ANTHROPIC_API_KEY` and the
others), or a provider is already signed in, first run asks no "which model"
question: it uses that provider with its recommended model and says so in one
line ("Using Anthropic (claude-…) from ANTHROPIC_API_KEY; change it with the
model control"). The provider card appears only when nothing usable is found. A
custom provider's key typed at the key prompt is now really used (in 3.4.8
every message then failed with "No model is set up yet.").

### A command you typed or a form you submitted is the request

A slash command typed in full, or a form you submitted from a menu, runs at
once and says how to put it back where that is possible (checkpoint restore,
rewind and settings import included). The forms no longer say "nothing is done
until you confirm it": their submit button names what it does (`Send`,
`Approve (at most 25.00)`) and the consequence sentence the typed line shows is
shown beside it. A risky line the model proposes still asks. `/google connect`
installs what it needs without a question and says what it is doing while it
does it (`Installing Google Cloud SDK, 63 MB, into ~/google-cloud-sdk: 50%
downloaded`). A tool server you add with `/mcp add` starts without a trust
question.

### The trust question only where it means something

A folder with no hooks file and no tool servers (MCP) of its own is trusted
without a question: trusting it would let nothing run that your permission mode
does not already govern. A folder that brings them is asked about as the
program opens, before anything runs, with the cursor on "Trust this workspace"
and a sentence naming what trusting lets run. "Keep restricted (read-only)" now
means it: no file is changed and no command runs, and the folder's own hooks
and tool servers stay off. A folder that later gains a hooks file or a tool
server is asked about then, before any of it runs. Headless runs and the
daemon's runs ask nothing on opening and behave as 3.4.8 did.

### Data that reads and refreshes by itself

- The web app's lists (mail, calendar, dates, memory, people, paired devices,
  check-ins, CI watches, voice, Tailscale, sessions, checkpoints) follow the
  daemon's change events, and re-read when a view opens, the window regains
  focus or the connection comes back. A newer web app reloads by itself when
  nothing is being typed, streamed or filled in, and otherwise offers "Reload
  to update".
- The terminal Work screen reads each work's state when it opens and on each
  change; the Security screen audits when it opens and when a device is
  paired; the tool-server screen updates when a server connects.
- Calendar subscriptions due for a refresh are read before each calendar read.
- A tool server refused for missing credentials reconnects once the secret is
  saved, and one not started yet starts on first use.
- An edited `hooks.json` is read again before the next hook fires.
- After `/codebase build`, the index follows the files GoodVibes writes.
- Joining a machine group, relay pairing and saving a service setting finish in
  the same run, with no command to run afterwards. Joining a group answers
  before the daemon restarts itself to bring the group up.
- Wake-word listening restarts by itself when an input device changes or the
  app regains focus.
- Model lists and the model catalog are read again at every start;
  `provider.refreshListsAtStart` ("Read model lists again at every start")
  turns that off for a machine with no network.
- `update.releasesUrl` is followed while the daemon runs: a changed address is
  used at the next check, as `config set` says a running daemon applies most
  keys.
- Setting a plugin's trust tier starts a plugin whose switch-on that tier
  refused: the switch-on stays recorded, so `/plugin trust <plugin> <tier>`
  starts it whenever you set it, also after the app was restarted.

### The model keeps working

- A tool call that does not match its schema (a missing or extra field, a wrong
  type, an unknown value) goes back to the model as that call's result, naming
  the field, what was received and what is accepted, and the turn goes on.
  Obvious shapes are repaired first and the repair is noted. You see one plain
  row: `The model's call to <tool> was malformed; it was asked to send it
  again.` A model that sends the same malformed call three times in a row stops
  with a plain reason.
- A write refused in a restricted folder also goes back to the model ("This
  folder is restricted: no file can be changed and no command run until it is
  trusted.") instead of ending the turn.
- When Jev refuses an action, the model is told Jev's reason, and is offered
  the answers the decision allows (revise, defer), so it can change course.
- The model is told its working folder, the operating system, the date, and
  whether the folder is a git repository, with its branch and whether it has
  uncommitted changes.
- Every example in the built-in prompts is valid for the tool it describes, and
  every tool description lists every mode its schema accepts.
- Helper agents read your instruction files the same way the main conversation
  does.
- Compaction sizes follow the model's context window, and the system prompt is
  not sent again where the provider already holds it.
- With no decision model set, native work `Start` starts, and your own profile
  and Dates writes save; a decision model that fails leaves nothing behind to
  resume and says so.

## Safety

- **An ask that weakens a protection opens on No and says it is saved.**
  Turning off the sandbox, loosening a security, judgment or payment setting,
  and the other asks that make a lasting change open with No selected, in every
  program, and say how long the change lasts ("Saved to your settings: it stays
  off until you turn it back on"), never "once".
- **The approval card's keys.** Saying why you refuse has its own key, `w`
  (`w say why`); once the reason field is open every key is text until Enter or
  Esc, so typing a reason can no longer fire `y`, `n` or `a`, and Enter refuses
  with the reason. Numbered choices answer to their numbers, on the card and on
  every list that shows numbers. A paste is never an answer.
- A model that stops being free is decided through your permission mode, and
  its card says what the price became.
- "This exact command" compares the command and the folder it runs in, so `.`
  and no folder match the same command.
- What one decision request sends is written down in
  [decision-model policies](../decision-model-policy.md#what-one-decision-request-sends).

## The web app

- A draft belongs to its chat: kept when you switch views or reload, never
  carried into another chat.
- With no model connected, the model button says "Connect a model" and opens,
  and connecting starts from it.
- Providers can be signed in again and given an API key from Settings, Models
  and providers ("Sign in again", "Add API key").
- "Compact" tightens rows and spacing in every list and the transcript; Back
  closes an open detail before leaving the view.
- Every focus ring reaches 3:1 contrast in every theme; the focused approval
  card shows its keys for approve, deny and stop.
- Key labels follow the platform (Cmd on a Mac). A code block whose language is
  not known carries no language label.
- On a phone the chat title keeps its room: the permission chip shrinks to its
  icon and one word.
- The app loads the chat first and the other views on demand, and keeps only
  the messages near the screen mounted; scroll position, find in page and jump
  to message still work. `Ctrl+F` searches a long chat.
- Settings, Voice shows an install another program started; Settings opens with
  focus in its search field.
- Files can be attached to native requests.

## The terminal app and the Agent

- `/model` (and `/model use` with no model named) opens the full model picker,
  with price tiers and the Recommended list.
- Copying uses a clipboard program when one is present (wl-copy, xclip, xsel,
  pbcopy, clip.exe) and says "Copied" only when it confirmed; otherwise "Sent to
  your terminal's clipboard". A setting turns mouse capture off for people who
  select with the terminal.
- Actions on `Alt` and `Ctrl+Shift` keys that readline, tmux or macOS Terminal
  swallow each have a second default key; none was removed.
- The notice count shows the newest notice's subject beside it.
- The setup checklist has `s skip for now` on a topic, and `s bring it back` on
  a skipped one.
- The slash menu lists only commands that exist; the provider picker no longer
  lists the internal decision router.
- Schedules read in words with the schedule beside them (`every weekday at
  09:00 (0 9 * * 1-5)`), and the task under it.
- Purchase and card rows read as one line: what, from whom, the amount with its
  currency, and when it goes ahead.
- The terminal app's pairing screen shows the QR code and its address whole on
  their own when the window is short, with one key for the details; in the
  Agent the pairing link is one block whose copy key (`Ctrl+Y`) copies the real
  link.
- The Work view offers stop only once a work has been started; a work that was
  never started offers start and check.
- `/update daemon` follows a daemon update on one line updated in place, which
  names the file downloading, which of the release's files it is and how much
  of it has arrived (`downloading <file> (<n> of <count>): <percent>%`); where
  the output cannot update a line in place, such as a command run from the
  Agent workspace, a new line comes only when the file's percentage has moved
  by 5 points or a file finished.
- The installer's advice to put its folder on your PATH arrives as one notice
  naming every program in that folder, not one notice per line per program.
- Google setup's mail check says what to do for what you saw: when Gmail
  refuses the app password (over IMAP or SMTP) the steps to make a new one are
  shown right there; when a mail server cannot be reached it names the server
  and says this machine's network or that address is the cause. A Google
  request that needs a new consent shows its link and continues by itself once
  you approve.
- The Agent's workspace has one name for approvals and running work ("Work &
  Approvals"), offers importing the terminal app's settings as one key, and
  every hint it prints names something that works.
- A channel send with no target uses the default one; a channel plus a link is
  one target with a link.

## The command line

- `goodvibes secrets set <KEY>` with no value asks for it without showing it, or
  reads it from standard input when piped; the value form still works.
- A usage error prints one line and the command's usage line, as JSON with
  `--output json` or `stream-json`. An unknown option lists only the options
  that command uses. A `-c key=value` error names the key and the values it
  accepts.
- `goodvibes <word>` with no terminal is refused with exit 2 and a plain line.
- `goodvibes run --output stream-json` starts with a frame announcing the
  session (id, model, working folder, permission mode), and the prompt may come
  from a file (`--prompt-file <path>`) or standard input (`-`).
- The GitHub Action splits `command` and `args` the way a shell splits words,
  with nothing expanded.
- **https on the local network** is new and opt-in: `goodvibes-daemon webui
  enable --lan --https` serves the web app over https on port 3443 with a
  certificate from an authority limited to this machine's own names and private
  addresses. It has not been tried on a real phone yet.
- `docs/llms.txt` indexes the parts of the reference beside `docs/llms-full.txt`.

## For agents and editors

- `goodvibes acp` answers an editor's prompts, and a failed run is reported to
  the editor as a failure, not a refusal.
- Headless runs: the first `stream-json` frame and `--prompt-file`, above.
- A hook before a model request (`Pre:llm:chat`) can now add context, which goes
  to the model with that request; the hook points that only observe (after a
  chat, a tool server call or a compaction, and their failures) no longer claim
  they can.

## Fixed on the way

- Uploads failed after `~/.goodvibes` was made private (present since 3.1.2).
- `/mcp accept-tools` read the server's old tool list instead of the new one.
- The compaction preview estimated the same size whatever the model's window.
- Checkpoints the terminal programs make, including one made before the daemon
  connection is up, now reach web clients; a checkpoint notice to the daemon is
  never given up for being slow.
- The relay announces only real changes, not every reconnect attempt.
- A typed device name is given to the device.
- `/work new` registers the folder it is asked for, and a refused folder says
  why with nothing kept.
- A plugin command's real name is `/plugin-<plugin>-<name>`; the docs said
  otherwise.
