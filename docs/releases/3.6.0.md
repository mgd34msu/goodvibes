# GoodVibes 3.6.0

GoodVibes 3.6.0 consolidates the platform around one user, one daemon home, and
the 14 Places UI across the terminal app, Agent, and web UI, while hardening
multi-project isolation, daemon startup/shutdown lifecycles, and error handling
across every layer.

## Upgrading

- **All programs must be on 3.6.0.** Run the terminal app, Agent, daemon, and
  web UI on 3.6.0 together. The installer and updater replace every program as
  one suite.
- **Daemon records live in the daemon home.** Shared sessions, approvals,
  watchers, channel policies, triggers, cluster identity, plans, and logs live
  under `<daemon home>/records/.goodvibes/` regardless of which folder the
  daemon starts in. On first start, 3.6.0 carries existing 3.5.0 records
  forward automatically without deleting the original files.
- **Going back to 3.5.0.** Your sessions, settings, memory, schedules, paired
  devices, providers, and remembered permission rules remain intact if you roll
  back to 3.5.0.

## Highlights

### Places UI and capability discovery across every surface

- All 14 function groups (`Waiting for you`, `Automation`, `System`,
  `Sessions`, `Mail, calendar and channels`, `Work and agents`, `Money`,
  `Devices and network`, `Code and changes`, `Tools and extensions`,
  `Permissions and safety`, `Memory and knowledge`, `Models and providers`, and
  `This conversation`) are now first-class Places in the terminal app, Agent,
  and web UI, replacing dozens of fragmented slash commands with one shared
  declaration layer.
- `Ctrl+K` in the web UI searches and runs daemon capabilities directly via
  `capabilities.find`, displaying long outputs cleanly in the result pane
  rather than truncating them in a toast.
- Terminal `find` and `do` subcommands are available across `goodvibes`,
  `goodvibes-agent`, and `goodvibes-daemon` for scriptable discovery and
  execution.
- Tailscale Serve controls are available in Devices and network across the
  terminal programs and web UI, and duplicate power / Tailscale panels in web
  settings have been deduplicated.

### Consistent single-user authority and 5 permission modes

- Every credential of your install — web sign-ins, paired devices, the local
  operator token, scripts, and terminal apps — acts as you immediately across
  every project and shared resource (limited only by a narrow token's stored
  scope list).
- Removed unnecessary program-registration socket checks (`programs.sock`) and
  per-device project/shared-kind grant clutter, keeping real security
  boundaries focused on models, untrusted external text, channel guests/strangers,
  and peer nodes under the five permission modes (`ask-me`, `jev-decides`,
  `just-vibes`, `yolo`, `plan`).
- Provider sign-in URLs, pairing links, and notification addresses are shown
  once in the reveal pane rather than written into conversation history.
- Pasted lines beginning with a slash that do not name a real command (such as
  `/secrets set ...`) are no longer forwarded to the model, while pasted file
  paths continue to work normally.

### Multi-project isolation and reliability

- Checkpoints, rewind plans/applies, skills, hooks traces, triggers, worktrees,
  CI watches, and session/task routes now consistently resolve the caller's
  explicit project (`x-goodvibes-project` / `workingDirectory`) instead of
  falling back to the daemon's own working directory.
- Projects on separately mounted or temporarily unmounted disks keep their
  identity cleanly and report unreachable folders without corrupting or
  recreating state.
- Stopping a failed piece of work releases all branches and worktree folders it
  created, and user-created CI watches run their repairs in their own project.

### Daemon lifecycle, concurrency, and failure honesty

- Single-flighted `DaemonServer.start()`, tracked boot-recovery tasks through
  clean shutdown, and added full subsystem rollback on startup failure.
- Added generation/epoch fencing across HTTP and LAN HTTPS listeners, project
  eviction locking for CI watch repairs, bounded caches/maps across long-lived
  daemon stores, and stale-lock recovery (including `-C` / `--git-dir` inspection
  and `SIGKILL` recovery) for git lock waits.
- Atomic temp-file writes and honest partial-failure reporting across config
  resets, settings sync, preset loads, secret deletions, carry-forward records,
  channel account setup/logout, and installer scripts.
- Bundled Bun invocations in the installer and uninstaller pass
  `--no-env-file --config=/dev/null` so repository configs never hijack
  installation.
