# GoodVibes 3.6.1

Patch release fixing post-upgrade daemon version skew, OpenAI subscription model discovery, and voice wake-word capture buffering.

## Fixed

### Managed daemon restart after suite updates
- When `goodvibes` or `goodvibes-agent` self-updates the installed suite on disk (including launch-time auto-update) and replaces `goodvibes-daemon`, the updater now restarts the running managed daemon service (`systemd`, `launchd`, or Windows Scheduled Task) before relaunching the terminal app.
- Previously, the updater only printed a restart hint to stdout before re-exec'ing into the alternate screen, leaving the previous daemon process running until manually restarted.

### Incompatible daemon refusal and automatic recovery
- Wired the terminal app's daemon compatibility status into both `useTuiDaemonRefusal` and `useConnectedHostRefusal`, and raised the TUI and Agent daemon build floors to `3.6.0`.
- Delegated agent work (`work.delegate`) and background posters (`hooks.trace.post`, `permissions.audit.post`, `notifications.send`) no longer dial an incompatible older daemon and fail with `Unknown gateway method` or misleading `auth_required` errors. Instead, the mismatch and restart command (`goodvibes-daemon restart-service`) are surfaced once, and the attach handshake reprobes periodically so restarting the daemon heals the live terminal session automatically.

### OpenAI subscription live model discovery
- `fetchOpenAISubscriptionModelIds` now passes `client_version=<platform-version>` and `OpenAI-Beta: responses=experimental` to `https://chatgpt.com/backend-api/codex/models`, resolving `400 Bad Request` live discovery failures on `openai@subscription`.

### Voice wake capture latency and drop throttling
- `parecord` now passes `--latency-msec=80` and `pw-record` passes `--latency 80ms` so audio arrives in 80 ms frames instead of PulseAudio's default 2000 ms (64 KB) bursts that dropped 80% of microphone frames.
- `WakeListener` now honors its 30-second dropped-frame report interval across consecutive bursts instead of logging every burst.
