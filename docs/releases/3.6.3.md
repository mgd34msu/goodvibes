# GoodVibes 3.6.3

Patch release fixing frozen progress reporting on daemon-delegated work, decision-model secret fallback for service-managed daemons, and high terminal redraw CPU while waiting.

## Fixed

### Live step progress for daemon-delegated work
- `daemon-work-delegation` now truncates multi-line delegated prompts to a single-line title and summarizes `work.run.steps` on every update (`planning steps on the daemon`, `N/M steps done · running: <step titles>`, `checking: ...`, and `needs you in Work (Ctrl+G then w)`), instead of sitting on a static `"running on the daemon"` line for the entire run.

### Decision-model secret-store fallback for service-managed daemons
- When `goodvibes-daemon` runs under `systemd` or `launchd` without interactive shell environment variables, `composeJudgment` and `decisionModelSet` now fall back to reading `TYPESAFE_API_KEY` (or configured `judgment.keyName`) from the daemon's secret store when `judgment.keySource` is default `env`, instead of reporting `"no decision model is in use"` and pausing finished work in `needs-you`.

### Terminal waiting CPU reduction
- `ActivityAnimation` now ticks at 250 ms (4 Hz) — and 1,000 ms under `display.reduceMotion` — instead of redrawing the entire terminal every 80 ms (12.5 Hz) while waiting on daemon work.
