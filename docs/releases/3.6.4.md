# GoodVibes 3.6.4

Patch release generalizing daemon shell environment hydration under service managers, unifying decision-model readiness across all callers, exposing live Work step progress at the daemon source for every surface, and normalizing remaining terminal spinner timers.

## Fixed

### Service-managed daemon login-shell environment hydration
- When `goodvibes-daemon` starts under `systemd` (`INVOCATION_ID` / `JOURNAL_STREAM`) or `launchd` (`XPC_SERVICE_NAME`), it now queries the user's configured login shell once at startup and merges missing environment variables into `process.env` in memory (supporting `bash`, `zsh`, `fish`, and POSIX shells, including `~/.bashrc` interactive guards, without overwriting unit-provided variables or writing any secrets to disk). Environment variables exported in shell startup files (`TYPESAFE_API_KEY`, provider API keys, custom tool tokens, `PATH` entries) now work directly inside the daemon without duplicating them into `secrets.enc`.

### Unified decision-model secret awareness across all callers
- Added a process-level stored-key probe registered by `composeJudgment` (and explicit `hasStoredKey` forwarding through `decisionModelReady`, `DecisionModelReadinessOptions`, `cliDecisionModelFacts`, and `decisionModelChoices`) so the permission gate (`jev-decides`), `status` / `doctor`, and Settings UI agree with `composeJudgment`. Judgment fallback targets now also honor the same secret-store fallback when `keySource` is default `env`.

### Live Work step progress at the daemon source
- Added shared `liveContractStatusLine` / `formatLiveStepProgress` in `platform/contract/live-progress.ts` and wired it into both `control-plane/routes/work.ts` (`work.list`) and `contract/operator-service.ts` (`summarizeContract`), so WebUI, Work board, CLI `work.list`, `goodvibes-agent`, and TUI all show live step progress while Work runs without duplicating lines.

### Normalized terminal spinner redraw cadence
- Aligned the remaining fast redraw timers in `orchestrator.ts` (80 ms → 250 ms), `hosted-turn-activity.ts` (`HOSTED_SPINNER_INTERVAL_MS` 80 ms → 250 ms), and `first-run-flow.ts` (120 ms → 250 ms) to the same 4 Hz cadence as `ActivityAnimation`.
