# GoodVibes 3.6.5

Patch release fixing false admission refusals (`NATIVE_EXECUTION_REFUSED`) on authorized native daemon Work starts when a live decision model is active.

## Fixed

### Native Work start admission instructions (`work-ledger.native-start`)
- Clarified the `decideAutonomous` instructions in `workflow/work-ledger/native-execution.ts` so the decision model knows the host has already verified owner authority, workspace scope, the active work claim (`existingActiveClaim: true`), and immutable source identities, and should start ordinary authorized work unless the goal or criteria are harmful, contradictory, or violate a stated constraint. Previously, live `jev` runs hedged below the high-stakes band (`confidence < 0.85`) and fell through into refusal (`422 NATIVE_EXECUTION_REFUSED`) on ordinary delegated work once the daemon had a live decision model key.
