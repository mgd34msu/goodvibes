# GoodVibes 3.6.6

Patch release fixing a planner deadlock on native daemon Work when a live decision model is active.

## Fixed

### Prevent planner deadlock on immutable native root criteria (`contract.plan-checks`)
- `runPlanChecksWithModel` in `platform/contract/plan-checks.ts` previously skipped `criterion-trace` and `plan-coverage` when `checkRootMeaning` was false (immutable `nativeSource` or fixed `originalSource` root criteria), yet still ran `criterion-shape` on those immutable roots. Whenever a live decision model rated a broad or delegated root criterion (such as `"Done as asked: review this codebase, give it a score out of 10"`) below `0.5` checkability, `plan-checks` demanded the planner restate it — which is forbidden by `checkNativeSourcePlan` — causing every repair attempt to deadlock until the work failed with `"the decision model rejected the plan, and no repair was eligible"`.
- `readCriterionShapes` is now gated on `checkRootMeaning` alongside `checkTrace` and `checkCoverage`, while `checkUnits` (`unit-shape`) continues validating every unit's derived acceptance criteria, role, and coverage of the immutable root criteria.
