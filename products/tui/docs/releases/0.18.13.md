# 0.18.13

`0.18.13` is the platform/TUI boundary separation release. The TUI is now a thin rendering, input, and wiring layer built on `@goodvibes-jev/engine/platform@0.18.29`. Thousands of lines of duplicated, forked, and dead code have been removed and replaced with platform imports.

## Why This Release Matters

The goodvibes-tui and goodvibes-platform were split from a single codebase, but the split was incomplete. The TUI still contained full copies of platform classes (Orchestrator, ConversationManager, plugin loader, tool registration, runtime services), dead code from abandoned local daemon files, and duplicate store domain/reducer implementations. This release completes the separation.

The principle: **the platform is the platform, the TUI is one surface built on it.** The platform provides orchestration, tools, providers, config, sessions, channels, automation, knowledge, daemon, and infrastructure. The TUI provides terminal rendering, keyboard input, panels, and the wiring that connects platform services to the terminal.

## What Changed

### Dead Code Removed (~1,600 lines)

Four daemon files (`facade.ts`, `facade-composition.ts`, `surface-policy.ts`, `types.ts`) were stale forks of platform code that nothing in the TUI imported. The TUI's `cli.ts` already imported `DaemonServer` from the platform. Two UI read-model files were dead code superseded by the platform's implementations.

### Forks Replaced with platform Imports (~2,200 lines)

Seven files that were near-identical copies of platform code were replaced with thin re-exports:

- **Orchestrator** (736 → 3 lines): The platform's Orchestrator already had every method the TUI used, including `getSpinner()`. No subclass needed.
- **Plugin loader** (305 → re-exports): The platform now accepts `additionalDirectories` and `entryDefault` options, so the TUI no longer needs to fork the loader to add `.goodvibes/tui/plugins`.
- **Tool registration** (187 → re-export): The platform's `registerAllTools` takes `surfaceRoot` as a parameter.
- **Subscription providers** (128 → re-export): Identical OAuth configs.
- **API key resolution** (123 lines removed): The platform now has `config/api-keys.ts` with the canonical 30+ provider-to-env-var mapping.
- **Permission types** (4 type definitions removed): Imported from platform instead of redefined.
- **Store domains + reducers** (4 files → re-exports): Conversation domain, permissions domain, and both reducer files were byte-for-byte identical.

### ConversationManager Refactored (776 → ~450 lines)

The TUI's `ConversationManager` was a standalone class that duplicated all of the platform's message management (CRUD, branching, persistence, compaction, undo/redo) plus added ~430 lines of terminal rendering. It now extends the platform's `ConversationManager`, inheriting all message management and keeping only the rendering layer:

- `TuiBlockMeta extends BlockMeta` adds rendering fields (`blockIndex`, `startLine`, `lineCount`, `collapseKey`)
- All message methods are inherited from the platform base class
- Override methods call `super.method()` first, then mark display dirty

### Health Monitoring Renamed (20 files)

The platform generalized `PanelHealthMonitor` to `ComponentHealthMonitor` (since health monitoring is infrastructure, not a TUI concept). The TUI was updated to match: `panelHealthMonitor` → `componentHealthMonitor` throughout runtime, panels, diagnostics, bootstrap, and tests. Deprecated `Panel*` aliases remain for backward compatibility.

### RuntimeState Aligned with platform

The platform's `RuntimeState.panels` changed from `PanelDomainState` to `Record<string, unknown>` (surfaces define their own panel shape), and `uiPerf` became `surfacePerf: SurfacePerfDomainState`. The TUI's store was updated to match while preserving its typed `PanelDomainState` through casts.

### Clipboard Split

The platform's `clipboard.ts` contained both terminal-specific code (OSC 52 copy) and platform-level code (system clipboard paste). The terminal copy was moved to the TUI; the platform paste functions remain in the platform.
